## 0. 세 줄 요약

1. **전체 카탈로그를 실제로 주는 소스는 소수다.** CU, 오리온, 프랜차이즈 메뉴판 12곳뿐이다.
   나머지는 "행사/PB 목록"이거나 "보도자료"다. `CLAUDE.md` 2.1의 차집합 전제가
   전 소스에 그대로 성립하지 않는다.
2. **소스가 두 유형으로 갈렸다.** (a) 전체 카탈로그 → 차집합 diff,
   (b) 보도자료 → 증분 피드 + 본문에서 제품 추출. (b)는 `pipeline/diff.py`의 대상이 아니고
   `CLAUDE.md` 6장이 규정한 LLM 역할 4가지에도 없다.
3. **v1 수직 관통 대상은 CU가 맞다.** 전 카테고리 카탈로그(5,100건), 세션·토큰 없음,
   바코드 ID 있음, 행사 노이즈 없음 — 네 조건을 동시에 만족하는 유일한 소스다.

## 1. 소스별 표

등급 정의: **EASY** = 정적 HTML 또는 깔끔한 JSON / **MEDIUM** = JS 렌더링·미확정 파라미터
/ **HARD** = 봇 차단 또는 robots.txt 금지 / **BLOCKED** = 접근 경로 자체가 없음

`method`는 `targets.yml`의 값과 동일한 어휘를 쓴다: `static` | `xhr` | `playwright` | `press`.

## 3. diff 방식과의 궁합

### 잘 통하는 소스

| 소스 | 이유 |
|---|---|
| **CU** | 7개 전 카테고리 상시 카탈로그. 행사 목록이 섞이지 않음. 바코드 ID |
| **오리온** | 카테고리별 전체 카탈로그 + 안정적 `goodsno`. `badge=new`를 **대조군**으로 둘 수 있어 diff 정확도를 자체 검증할 수 있는 유일한 소스 |
| **스타벅스** | 1요청 전 카탈로그. 시즌 음료 교체 주기가 뚜렷해 diff 신호가 선명 |
| **배스킨라빈스** | '이달의 맛'이 매달 교체되는 구조 자체가 diff에 최적 |
| **맥도날드 / BBQ / bhc / 던킨** | 메뉴판 전체가 API로 그대로 노출. 행사 노이즈 없음 |
| **교촌 / 도미노 / 맘스터치** | 메뉴 수가 적고 상시 메뉴 위주 → 변동이 곧 신메뉴 |

프랜차이즈 채널이 편의점보다 diff 궁합이 좋다. **전부 상시 메뉴판이고 행사 목록이 없기 때문**이다.

### 통하지 않거나 주의가 필요한 소스

| 소스 | 판정 | 이유 |
|---|---|---|
| **세븐일레븐** | **나쁨** | 목록 2,600건 중 **91%가 월간 행사 상품**. 매월 1일 즈음 전량 교체되어 diff가 수백 건 튄다 |
| **보도자료 9곳 + 신세계 뉴스룸** | **적용 대상 아님** | 게시물이 사라지지 않으므로 "지난주에만 있는 항목 = 단종"이 성립하지 않는다. `after=<지난주>` 증분 피드가 맞다 |
| GS25 | 보통 | PB 203 + 차별화 584 = 787건은 안정적. 행사 1,723건은 노이즈 → **행사는 보조로 격하** 권고 |
| 이마트24 | 보통 | PB 538 + FF 178은 안정적. 행사 2,363건은 노이즈 |
| 메가MGC / 컴포즈 | 주의 | **고유 ID가 없거나 약해** 이름 해시 의존. 시즌 접두사(`[여름한정]`) 변경에 취약 |
| 파리바게뜨 | 보통 | 카탈로그가 크고 시즌 회전이 빨라 diff 건수가 과다해질 수 있음 |
| 홈플러스 | 주의 | 온라인 **배송 가능 품목만** 노출. 품절/재입고로 목록이 출렁일 가능성이 있다(추정 — 2주 검증에서 실측 필요). 신상이 아니라 재고 변동을 잡을 위험 |

### 이것이 의미하는 것

`CLAUDE.md` 2.1은 **모든 소스가 전체 카탈로그를 준다는 전제** 위에 서 있다.
실제로는 소스가 세 종류로 갈린다:

| 유형 | 신상 판별 방식 | 해당 소스 |
|---|---|---|
| (a) 전체 카탈로그 | 차집합 diff — 2.1 그대로 | CU, 오리온, 크라운, 프랜차이즈 12, 홈플러스 |
| (b) 부분 목록(행사·PB) | 차집합이되 **"목록 진입/이탈"이지 "신상/단종"이 아님** | GS25, 세븐일레븐, 이마트24 |
| (c) 보도자료 | 증분 피드(post id/date) + **본문에서 제품 추출** | 신세계 뉴스룸, FMCG 8곳 |

(c)는 `pipeline/diff.py`의 대상이 아니며, `CLAUDE.md` 6장이 규정한 LLM 역할 4가지에
**"산문에서 제품 레코드 추출"이라는 5번째 역할**을 추가해야 한다.
**코드보다 `CLAUDE.md` 6장 개정이 선행되어야 한다.**

## 5. 현 시점 리스크 3가지

### 1. 파이프라인이 하나가 아니라 둘이다 (설계 리스크 — 지금 결정해야 함)

`CLAUDE.md`의 파이프라인(`snapshot → diff → curate → publish`)은 **전체 카탈로그 소스만** 상정한다.
실제로 확보한 28개 소스 중 **9개(신세계 뉴스룸 + FMCG 보도자료 8곳)는 모양이 다르다** —
스냅샷도 차집합도 없고, `after=<지난주>` 증분 수집 후 **산문에서 제품을 추출**해야 한다.

지금 무시하면 나중에 `diff.py`에 보도자료용 분기가 파고들어 2.3(소스 격리)이 깨진다.

**필요한 결정**: (a) 보도자료 소스를 v1 범위에서 아예 뺀다, 또는
(b) `CLAUDE.md` 6장에 LLM 5번째 역할을 추가하고 `pipeline/extract.py`를 별도 트랙으로 둔다.
**v1은 (a)를 권한다.** 카탈로그 소스만으로 편의점·프랜차이즈·오리온·홈플러스가 커버된다.

### 2. P0 25개 전제가 깨졌다 (범위 리스크)

정찰 결과 **P0 25개 중 7곳을 확보하지 못했다.**

- **blocked 5** — 이마트, 투썸플레이스, 이디야, 뚜레쥬르, 롯데리아.
  전부 robots.txt 또는 봇 차단이다. **기술이 아니라 정책이라 노력으로 해결되지 않는다.**
- **unverified 2** — 버거킹, 피자헛. 브라우저 캡처 1회면 살릴 수 있다.
  → **버거킹은 2026-08-26에 확보했다.** 캡처는 필요 없었다 — 봉투를 만드는 코드가
  사이트에 실려 있었다. 남은 것은 피자헛뿐이다.
- 그 밖에 롯데마트가 3중 차단으로 P1 → P2 강등됐다.

게다가 살아남은 P0 중에서도 GS25·세븐일레븐·이마트24·홈플러스는 **전체 카탈로그가 아니다.**

- 마트 채널은 홈플러스 하나로 축소됐다. "마트 신상"이라고 부를 수 있는 수준인지 판단이 필요하다.
- 카페 채널은 P0 5곳 중 2곳이 빠져 스타벅스·메가·컴포즈만 남았다.

**필요한 결정**: P1 승격(크리스피크림·설빙 / KFC·노브랜드버거 / 할리스·커피빈)을 실제로 할지.
단 이들은 전부 `unverified`라 **승격 전 재정찰이 선행**되어야 한다.
이번 보고서에서는 임의로 priority를 바꾸지 않고 후보만 `targets.yml`에 주석으로 남겼다.

### 3. 제품 동일성 판정이 프로젝트의 성패를 가른다 (핵심 기술 리스크)

`CLAUDE.md` 2.1의 차집합은 "같은 제품을 같다고 판단할 수 있다"를 전제한다. 그런데:

- 바코드는 편의점에만 있고, 나머지 24개 소스는 **브랜드 내부 ID 또는 이름 해시**다.
- 이름은 CU에서 12자에 잘리고, POS 접두사·시즌 접두사·`™` 기호가 붙는다.
- **이름이 한 글자만 바뀌어도 "단종 1건 + 신상 1건"으로 잘못 잡힌다.**
- 스타벅스는 같은 상품이 여러 카테고리에 중복 노출되어 **1,179건 중 실제 977개**다.
  dedup을 빠뜨리면 첫 주부터 중복 신상이 발행된다.

이것이 `CLAUDE.md` 8장 3단계 "2주 검증"에서 **실제로 확인해야 할 단 하나의 질문**이다.
diff 결과 건수가 아니라 **오탐(같은 제품인데 신상으로 잡힌 건)의 비율**을 봐야 한다.

> 차점 리스크: **가격이 프랜차이즈 채널에서 기본값 `null`이다**(14곳 중 11곳 미제공,
> 스타벅스는 `price` 필드가 있지만 1,179건 전부 빈 문자열 — 실측 확인).
> `CLAUDE.md` 4장은 `price` null을 예외로 허용하지만 이 채널에서는 정상 상태다.
> 웹 UI가 가격을 전제로 설계되면 프랜차이즈 카드가 전부 비어 보인다.
> 대신 **제품 설명문이 공짜로 딸려온다**(스타벅스 `content`, bhc·BBQ `description`,
> 배스킨라빈스는 해시태그로 `tags`까지) — `curate.py`의 40자 blurb를 창작할 필요가 없어
> 6장의 "없는 정보 생성 금지"에 오히려 유리하다.
