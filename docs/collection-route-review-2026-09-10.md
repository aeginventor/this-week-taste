# 수집 경로를 역할별로 다시 비교한다

> 같은 날 후속 제품 결정: 모든 후보의 공식 확인을 필수로 하지 않는다(ADR-0020).
> GS25·돈찐·최근 쇼츠의 새 표본과 현재 추천은 [후속 조사](content-route-check-2026-09-10.md)를 따른다. 아래는 그 전 비교 기록으로 보존한다.

**기존 목록 수집은 유지하고, 일반 콘텐츠의 후보 발견과 공식 정보의 확인을 작은 표본으로 따로 시험하는 편을 제안한다.**
공개 API는 우선 상품 동일성 확인에 쓴다. 기사 추출기를 더 다듬거나 운영 소스를 추가하지 않았다.
이는 AI의 추천이며 사용자가 운영 도입을 결정한 것은 아니다. 확인일은 2026-09-10 KST다.
같은 날 후속 확인에서는 W36만 보던 비교를 과거 성공 관측까지 넓혔다. 후와후와 빵은 W35 GS25 목록에 이미 있어 ‘기존 수집 밖의 새 후보’라는 추천 근거를 철회했다. 아래에 비교 기간과 후속 시험의 채택·보류 기준을 보강했다.

## 이번에 실제로 확인한 범위

공개 페이지·API 문서·약관을 읽고 기존 W36 저장 카탈로그와 상품 이름 후보를 대조했다.
원문·이미지를 새로 아카이브하거나 전체 목록을 다시 수집하지 않았다. API 인증키 신청·유료 계약·계정 로그인도 하지 않았다.
아래의 ‘본문 확인’, ‘검색 설명만 확인’, ‘접근 실패’, ‘명세만 확인’을 구분한다.
이 표본은 후보를 찾기 위해 고른 사례다. 시장 전체 커버리지나 자동 추출 정확도를 계산할 분모가 아니다.

## 작은 검증: 목록과 다른 경로가 무엇을 더 주는가

비공개 저장소의 W36 스냅샷에서 공백을 제거한 이름 문자열로 후보를 찾았다. 이 단순 검색을 상품 동일성 판정으로 쓰지 않았다.
식품사 발표 두 건·일반 글 두 건을 대조했고 원문은 복제하지 않았다. 예시를 늘리려고 규칙이나 모델을 튜닝하지 않았다.

## 후속 확인: 기간과 관측 범위를 맞춘다

식품 비교군은 **2026-08-10~16에 게시된 국내 편의점 포장 스낵·빵**으로 고정했다. 앞서 읽은 농심 발표의 4종과 개인 후기의 우유 쫀득빵 1종, 총 5개 이름 후보다. 두 본문과 게시일은 다시 확인했다. AI가 고른 편의 표본이며 전체 글을 빠짐없이 수집한 결과가 아니다.
같은 주의 W33과 후속 W35·W36 저장 목록을 구분해 읽었다. 비교 입력 41개 스냅샷의 지문·조회 문자열·일치 이름은 비공개 `research/collection-review-2026-09-10/comparable-cohort.json`에 보존한다. 이름을 보고 찾은 후보이지 자동 SKU 매칭 결과가 아니다.

이 5종에서는 **2종이 과거 목록의 이름 후보와 겹쳤고 나머지 3종은 이름 검색으로 찾지 못했다.** ‘새로 확인된 출시 3건’, ‘커버리지 40%’로 바꾸지 않는다. 첫 비교에서 일반 글의 증분 가치를 너무 일찍 기대한 부분은 위 반례로 수정한다. 공식 근거를 찾지 못한 것은 출시하지 않았다는 뜻이 아니다.

카페는 [기존 8월 24~30일 비교](data-route-study-2026-09-09.md)의 호지 라떼·블랙 라떼·아이스 변형·퓨어 호지차 사례를 재사용한다. W35 8월 24일 관측은 공식 발표 27일·본문 사건 28일보다 앞이고 W36 31일은 뒤다. 발표가 더해 주는 신규/시즌 복귀 맥락과 온도·규격 연결의 모호함을 확인한 사례다. 식품 5종의 분모와 섞거나 과거 모델 추출 성공률로 읽지 않는다.
6월 엽떡 발표·7월 하레하레 소개·2020년 유튜브 영상은 경로의 역할 사례로만 남긴다. 이 기간의 성과에 넣지 않는다. 같은 기간 Instagram·카페 원문·시청한 YouTube 표본은 확보하지 못했으므로 그 경로의 증분 가치는 미측정이다.

## 우선 시험할 세 경로 — 운영 채택 전 비교

1. **기존 목록 후보 + 편의점·식품사 공식 발표 대조.** 이미 있는 후보에 출시 근거를 붙일 가치부터 잰다. 농심 4종처럼 판매 채널이 다른 사례와 날짜 없는 발표를 함께 넣고, SKU 연결이 안 되면 계열 수준에서 멈춘다. 뉴스룸 1곳의 규칙을 개선하는 대신 서로 다른 브랜드의 같은 기간 소표본을 비교한다.
2. **일반 블로그·유튜브에서 후보 발견 → 공식 확인.** 증분 가치는 아직 입증되지 않았다. 후와후와처럼 과거 목록에 이미 있던 제품을 다시 찾는 경우부터 걸러야 한다. 같은 기간·제품 범위의 공개 글·영상 링크를 소수 골라 읽고, 과거 성공 관측과 겹침·공식 근거 미확보·별도 후기 정보를 나눠 실제 검토 분수를 기록한다. 동일 홍보자료의 재게시를 묶고 협찬 표기가 없는 글도 자동으로 일반 후기 확정하지 않는다. 플랫폼 API의 자동 추출은 권리·보관 조건을 해결한 뒤 별도 시험한다.
3. **푸드QR 바코드 소표본 조회.** CU의 중복 등록 두 사례와 정상 단일 등록을 함께 골라 규격·제조사 연결 가능 여부를 잰다. 제조보고번호를 판매 SKU 키로 대체하지 않는다. API 활용 신청/키가 필요한 후속 시험이며 이번에는 문서만 검증했다. 실패가 많으면 HACCP 이름 조회를 무조건 이어 붙여 복잡하게 만들지 않고 원인을 먼저 기록한다.

통과 기준은 테스트 수가 아니라 새로 얻은 유효 정보·공식 확인 가능성·검토 부담이다. 시장 전체를 덮는다는 주장이나 정답률 목표를 이 선택 표본에서 만들지 않는다.
계절 복귀를 제품 화면에서 어디까지 다룰지는 미정으로 유지한다. 이번 정리는 그 제품 선택을 대신하지 않았다.

### 다음 시험에서 무엇을 확인하고 언제 멈추는가

아래 ‘채택’은 **조금 더 큰 후속 비교 대상으로 남긴다**는 AI 제안이다. 운영 수집기·출시 확인 표시의 도입 승인은 아니다. 수집 권한과 보관 조건이 해결되지 않은 경로는 자동화 대상으로 채택하지 않는다.

| 순서·시험 | 고정할 입력과 확인할 질문 | 후속 비교에 채택 | 보류·축소 |
|---|---|---|---|
| 1. 목록 + 공식 발표 | 2026-08-10~09-06의 승인된 저장 자료·읽을 수 있는 공식 페이지. 편의점/식품과 카페를 따로 기록하고 신규·재등장·시점 없음·규격 모호 사례를 포함. 목록에 없던 **출시 사실·시점·판매처**를 더 주는가 | 서로 다른 브랜드에서 제품 계열과 명시적 출시 사건을 대응시킬 수 있고, SKU 미확인을 그대로 보류하면서도 유용한 근거가 남음. 후보마다 확인 분수·보류 이유를 남길 수 있음 | 기사별 날짜 예외나 ‘아이스’를 지우는 규칙을 계속 추가해야 함, 행사 기간만 있음, 제품 대응이 불명확함. 이 경우 자동 연결은 보류하고 공식 원문 링크 참고 역할만 유지 |
| 2. 일반 글·영상 → 공식 확인 | 1번과 같은 기간·채널·제품 범위. 직접 읽거나 시청한 표본만 사용하며 현 주차 외 과거 성공 관측도 대조. 기존에 없던 제품 단서를 더하는가, 후기를 더하는가 | 한 작성자의 한 사례에 그치지 않고 별개 작성자/시점에서도 기존 수집 밖의 제품 후보가 공식 정보로 대조됨. 겹치는 후보를 제거한 뒤에도 정보가 남고 검토 시간을 기록함 | 전부 기존 제품·홍보 복제이거나 공식 제품 대응을 못 찾음. 후기만 유용하면 후기 참고 경로로 역할을 축소. 원문 접근 실패·검색 설명만 확보한 영상은 미검증으로 남김 |
| 3. 푸드QR 동일성 조회 | 활용 신청 후 CU 중복 등록 두 쌍과 정상 제품 두 건. 같은 바코드 조회는 재사용하고 판매 등록 ID는 유지. 바코드·규격·제조사를 확인할 수 있는가 | 중복 등록 쌍의 제조사·규격 대응을 보강하고 정상 제품을 잘못 합치지 않음. 응답 필드와 시점·불일치 이유가 남음. 출시 판단 없이 동일성 보조로 제한 | 이름만 비슷함, 제조보고번호만 있고 판매 규격을 못 가름, 미등록·오래된 정보·상충 값이 남음. 추측 병합이나 연쇄 API 추가 없이 보류 |

공통 기록 항목은 입력 URL/관측 시각, 실제 읽은 범위, 과거 목록과의 겹침, 제품 계열/SKU 대응 수준, 출시 주장/미확인, 후기의 출처, 중복 홍보 묶음, 검토 분수·보류 이유다. 선택 표본의 통과율을 출시 정확도나 운영 절감 시간으로 보고하지 않는다. 시간 허용치가 필요한 운영 도입 결정은 실제 분포를 얻은 뒤 사용자와 정한다.
