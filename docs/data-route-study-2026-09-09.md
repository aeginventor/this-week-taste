# 공개 API와 공식 출시 근거의 역할 비교

> 2026-09-10 정리: 아래는 당시 판단과 실패를 보존한 기록이다. 기사 개선은 중단하고 [동결 코드와 재현 안내](../research/launch-study-20260910/README.md)로 분리했다.

확인일: **2026-09-09, KST**. 사용자는 후속 첫 단위로 **카탈로그 + 공식 발표의 격리 연결 실험**을 선택했다. 운영 도입·API 대체·시즌 제공 범위는 미정이다.
관련 결정: [ADR-0018](adr/0018-discovery-and-launch.md), [ADR-0019](adr/0019-publication-input-integrity.md).
기존 보도자료 수집 기각: [ADR-0016](adr/0016-press-feed-sources.md).

## 먼저 구분할 현재 상태

| 상태 | 실제 근거와 한계 |
|---|---|
| 해결·재현 검증 | W35→W36 CU에서 같은 바코드·이름·가격의 옛 등록과 새 등록이 공존했다. 옛 구현은 새 등록 28123·28108을 발행했고 입력 순서를 뒤집으면 다른 등록을 골랐다. 현재는 주키를 먼저 대응하고 과거 관측과 겹치는 두 등록을 보류한다. 동일한 저장 자료의 격리 발행은 W36 105→103건, 나머지 공개 ID·URL은 유지했다. |
| 해결·합성 검증 | 실패 뒤 남은 같은 주 부분 파일이 기준선 변경 후에도 병합되는 사례를 차단했다. 이월 파일의 주차를 최근 성공으로 잘못 세는 공백 계산도 수정했다. 실제 운영에서 해당 오발행이 있었는지는 미확인이다. |
| 구현했지만 운영 효과 미측정 | 입력 지문 검증, 같은 주 검증된 성공본 재사용, 소스 상태 표시, LLM 응답 형식 방어. 새 수집 주기에서 장애 감소·운영 시간 절감을 측정하지 않았다. |
| 미해결 | 공식 출시 근거의 자동 확보·제품 연결, 카탈로그 밖 출시 누락, 시즌 복귀 제공 범위, 범위 밖 식품 판정의 실제 품질, 제한된 관측 이력 밖의 재등록. 출시 정확도·전체 커버리지의 독립 정답 집합이 없다. |

현재 흐름은 `공식 사이트 목록 → 저장 관측 → 목록 변화·과거 중복 검사 → 상세 보강 → LLM 편집 → 입력 검증·병합 → 새 발견 표시`다.
LLM 편집 성공이 출시 확인을 만들지는 않는다. 첫 구현은 수집 구조의 최종 채택 결정이 아니다.

## 후보별 공식 계약

아래 URL은 모두 위 확인일에 조사했다. **문서를 읽은 것과 API 상품 조회 성공을 구분한다.**
현재 셸에서 관련 인증키 환경변수 이름은 확인되지 않았다. 다른 장소의 키 보유 여부까지 조사한 것은 아니다.
이번 실험은 인증·상품 조회 API를 호출하지 않았다. 공개 문서의 HTML·내장 명세·샘플만 읽었다.

### 1. 식품안전나라 I1250 — 식품(첨가물)품목제조보고

[공식 명세](https://www.foodsafetykorea.go.kr/api/openApiInfo.do?svc_no=I1250)

- **외부 이용용 Open API**. 식품·첨가물의 제조보고를 다룬다. 제조 원료·업소용 소스도 포함하며 소비자가 살 수 있는 소매 상품 목록과 같지 않다. 매장 조리 메뉴 전체를 포괄하지 않는다.
- `PRDLST_REPORT_NO`는 품목제조번호, `LCNS_NO`는 업소 인허가번호다. `PRMS_DT`를 요청 설명은 보고일자, 출력 설명은 허가일자라고 부른다. 어느 해석도 출시일은 아니다. `LAST_UPDT_DTM`은 최종 수정이다. 생산종료 여부가 재출시 이벤트를 뜻하지 않는다.
- 품목번호·업소명·제품명·보고일자 등의 조건과 페이지 범위가 있다. 상시 갱신 표기는 출시→보고→공개 지연의 보장이 아니다. 정확한 지연은 미측정이다.
- 현재 카탈로그에는 품목제조번호가 없어 직접 연결할 수 없다. 이름과 제조사로 후보를 찾더라도 포장 규격과 판매 단위를 추가 확인해야 한다. 음식점 소스의 제조보고를 완성 메뉴로 연결하면 오매칭이다.
- 무료 공공데이터 경로지만 이용 신청 약관을 계정에서 확인해야 한다. 공개 발행은 원본 전체 재배포 대신 최소 사실·출처 링크라는 기존 범위를 유지한다. 아래 공통 운영 공지가 오래된 서비스 메타정보보다 우선한다.

### 2. C005 — 바코드연계제품정보

[식품안전나라 명세](https://www.foodsafetykorea.go.kr/api/openApiInfo.do?svc_no=C005) · [공공데이터포털 목록](https://www.data.go.kr/data/15060549/openapi.do)

- 외부 Open API다. 공공데이터포털 항목은 **LINK**이며 같은 제공처로 연결된다. 두 독립 데이터원이 아니다.
- **2018년 이후 최신화 중단**이 명시돼 있다. 페이지의 ‘상시’나 포털 수정일 2025-08-26을 제품 데이터 최신화로 해석하면 안 된다. 최신 상품 수집 대체재로 추천하지 않는다.
- `BAR_CD`와 `PRDLST_REPORT_NO`가 연결된다. `PRMS_DT`는 보고·신고, `END_DT`는 생산중단, `CLSBIZ_DT`는 폐업이다. 출시·계절 재출시 정보는 없다. 문서에는 바코드·품목번호·변경일 조건이 있다.
- 무료, 포털 이용허락범위는 제한 없음이다. 제공처의 최신 운영 공지와 이용 신청 조건도 확인한다. 현재 CU 두 바코드의 실제 응답은 미조회다.
- 문서 샘플 30행에서 **한 품목번호에 여러 바코드**가 연결된다. 품목번호를 소비자 판매 SKU의 유일 키로 사용하거나 이 관계로 공개 ID를 합치지 않는다.

### 식품안전나라 최신 운영 공지와 발급

[2026-09-02 공지](https://www.foodsafetykorea.go.kr/api/board/boardDetail.do?bbs_no=apiNotice&ntctxt_no=1151919&menu_no=688&menu_grp=MENU_GRP33)
는 9월 3일 23시부터 전체 Open API에 적용한다고 안내한다.

- 전체 데이터 CSV 다운로드가 추가됐고 매일 0시 갱신한다. 인증키 신청 현황의 신청 서비스 목록에서 받는다.
- API 변경분 조회는 호출일 기준 최대 7일이다. 더 오래된 자료는 전체 CSV 이용을 권장한다.
- 1시간 100회 초과 호출 시 1시간 제한, 샘플 URL은 하루 100회 제한이다.
- 서비스 페이지의 500·2000 메타값이나 ‘증분 없이 100회’ 오류 설명과 차이가 있어 **최신 공지의 더 보수적인 제한**을 조사 기준으로 삼았다. 실제 적용은 인증 호출로 미검증이다.

[2026-07-08 공지](https://www.foodsafetykorea.go.kr/api/board/boardDetail.do?bbs_no=apiNotice&ntctxt_no=1151117&menu_no=688&menu_grp=MENU_GRP33)
는 별도 종료 공지까지 **09~19시 제한**을 안내한다. 최신 공지 목록에서 종료는 확인하지 못했다.
따라서 17시대 조사에서는 샘플 API도 호출하지 않았다. 문서의 샘플 표 분석은 이와 별개다.
API 메시지에는 당일 생성·변경분은 19시 이후 제공, 한 요청 1,000건 제한도 안내돼 있다.

[공식 발급 안내](https://www.foodsafetykorea.go.kr/api/howToUseApi.do?menu_grp=MENU_GRP34&menu_no=687):
식품안전나라 회원 로그인 → I1250 또는 C005 서비스의 Open API 이용 신청 → 약관·활용 목적 확인 → 인증키 및 서비스별 활용 신청 확인.
1인 1키이며 양도하지 않는다. 포털 LINK 항목에 일반 공공데이터 키를 넣는다고 같은 키가 되는 것은 아니다.
비밀값은 채팅·Git·명령 인자에 넣지 않고 개인 로컬 비밀 저장소에서 환경변수로 주입한다.
7일 넘는 작업 공백은 ‘마지막 성공 이후 변경분’만으로 복구되지 않으므로 CSV 재동기화가 필요하다.

### 3. HACCP 제품이미지 및 포장지표기정보

[공식 목록·내장 Swagger](https://www.data.go.kr/data/15033307/openapi.do) · [2024-02-07 V3 변경 공지](https://www.data.go.kr/bbs/ntc/selectNotice.do?originId=NOTICE_0000000003468)

- 한국식품안전관리인증원의 외부 REST API. HACCP 제품의 표시정보이며 전국·2017년 이후라는 메타정보가 있다. HACCP 제품 전부의 완전한 등록을 보장한다고 읽지 않는다. 카페·프랜차이즈 메뉴 전체에는 맞지 않는다.
- 현재 명세는 `B553748/CertImgListServiceV3/getCertImgListServiceV3`이다. 옛 V2 예제를 쓰지 않는다.
- `prdlstReportNo`, `barcode`, 제조원·판매원·용량·원재료 등을 제공한다. **출시일·수정일 필드와 날짜 증분 조건은 명세에 없다.** 행번호 `rnum`은 제품 키가 아니다.
- 요청은 품목번호·이름·제조원·유형·알레르기·페이지 등이다. **바코드 출력은 있지만 바코드 검색 요청변수는 없다.** 이름 조회 후 바코드를 대조하는 추가 단계가 필요하다.
- 무료, 개발·운영 자동 승인, 개발 트래픽 10,000, 운영 증설 신청 가능. 호출량 초기화·초당 제한의 구체 값은 신청 계정에서 재확인한다. 갱신 주기·지연·과거 버전 조회 보장은 확인한 명세에 없다.
- 포털 이용허락범위 제한 없음. 현재 프로젝트의 이미지 복제 금지는 유지한다. 표시정보가 의학적 검증 결과를 뜻하지 않는다.
- 키: 공공데이터포털의 이 서비스에서 활용 신청 후 `ServiceKey`. 실제 제품 조회 미수행. CU 이름은 판매처 접두어·잘림이 있어 이름만으로 일치를 승인하지 않는다.

### 4. 푸드QR 정보 서비스

[공식 목록·내장 Swagger](https://www.data.go.kr/data/15143798/openapi.do) · [식약처 데이터포털 소개](https://data.mfds.go.kr/)

- 외부 REST API. 푸드QR에 등록된 표시·제조·원재료·영양 등 11개 조회 기능이다. 모든 식품이나 매장 메뉴를 포괄한다는 보장은 없다.
- **현재 내장 명세는 `1471000/FoodQrInfoService02`**이며 `getFoodQrProdList02`, `getFoodQrProdMnfInfo02` 등을 제공한다. [2025-08-07 공지](https://www.data.go.kr/bbs/ntc/selectNotice.do?originId=NOTICE_0000000004276)의 Service01만 보고 구현하면 낡는다. 목록은 2026-08-11 수정, 02 전환의 별도 상세 공지는 이번 검색에서 확보하지 못했다.
- `BRCD_NO`, `IMRPT_NO`, `ELB_MNG_NO`로 연결할 수 있다. 언어·버전별 여러 행을 같은 출시로 중복 집계하지 않는다. `VLD_BGNG_YMD`/`VLD_END_YMD`는 **유효 기간**, `LAST_MDFCN_DT`는 수정이다. 최초 출시일이 아니다.
- 목록은 `brcd_no`, 이름, 버전, 유효기간, 페이지 조건을 받는다. 제조정보는 품목보고번호도 받는다. 변경 시점 커서나 전체 과거 이력의 보장은 확인되지 않았다. 표시정보의 실시간 조회라는 설명은 등록 지연의 SLA가 아니다.
- 무료, 개발 자동·운영 심의 승인, 개발 트래픽 10,000, 운영 증설 신청 가능. 포털 이용허락범위 제한 없음. 키는 이 서비스 활용 신청 후 `serviceKey`다. 정확한 운영 호출 제한·최신화 지연·CU 두 바코드 연결은 **미검증**이다.
- CU 바코드로 직접 좁힐 수 있어 **상품 연결 시험의 우선 후보**다. 실제 일치 결과를 받기 전 카탈로그를 대체하지 않는다.

### 5. 브랜드·유통사 제공 API와 GS1 Korea

CU/BGF리테일·GS리테일·SSG의 공식 도메인에서 API/OpenAPI/상품 키워드로 외부 개발자용 소비자 상품 목록·출시 피드 문서를 찾았다. 이번 범위에서는 사용 조건과 명세를 함께 확인할 수 있는 경로를 확보하지 못했다. **존재하지 않는다는 증명은 아니다.**
현재 CU·스타벅스·피자헛 수집기가 쓰는 JSON은 사이트 기능용 내부 API이며 외부 이용 계약이 공개된 Open API로 분류하지 않는다.

[GS1 Korea 제휴 안내](https://www.gs1kr.org/front/service/appl/BcdInfoAllianceBusiness.asp) · [코리안넷 DB 계약 안내·샘플](https://gs1.koreannet.or.kr/front/koreannet/dbApply.do)

- 바코드별 상품명·브랜드·용량·규격·제조사·이미지 등을 외부 사업자에게 제공하는 공식 API가 있다. 공개 무료 공공 API와 달리 **제휴·계약 방식**이다.
- 사업 모델 심사, 초기 연동 비용과 월 사용료 협의, 최소 12개월 계약이 안내된다. 고정 요금·요청 제한·갱신 SLA·변경 조회·출시일의 명세는 공개 안내에서 확인되지 않았다.
- 상품 등록·바코드 발급은 출시가 아니다. 상이한 포장 판매 단위를 연결할 때 규격을 함께 대조해야 한다. 카페 조리 메뉴의 포괄적 대체재로 볼 근거도 없다.
- 공개 발행 범위는 계약 사항이다. 이번에는 계약 신청·연락·유료 사용을 하지 않았다. 정확한 CU 연결 효과를 모르는 상태에서 연간 계약을 권하지 않는다.
- 공개 다운로드 XML 샘플 1개를 실제로 받았다(상품 조회 API 호출 아님). 해태 버터링의 `gtin`, 규격, `dstartavailable`, `dsysupdated` 값이 있다. 두 날짜의 계약상 정의는 샘플만으로 확인할 수 없어 출시일로 해석하지 않았다. CU 대상 응답도 아니다.
- 위해상품 판매차단 API는 별도 유통사 참여 서비스이며 위해·회수 정보다. 신상품 출시 경로로 도입할 이유가 없다.

### 7. 검색 API는 근거 탐색 수단이다

[네이버 이관·종료 공지](https://developers.naver.com/notice/article/32530) · [현재 API HUB 뉴스 명세](https://api.ncloud-docs.com/docs/naver-api-hub-search-news)

- 예전 **쇼핑 검색 API는 2026-07-31 종료**, HUB 이관 대상에도 없다. 남아 있는 옛 문서의 25,000회 안내로 신규 도입을 설계하지 않는다.
- 뉴스·웹 검색은 공식 출처 URL을 찾는 후보 경로다. 뉴스 API의 `pubDate`는 네이버에 제공된 시간(미제공 기사는 원문 제공 시간), `lastBuildDate`는 검색 결과 생성 시간이다. 출시일이 아니다.
- HUB 뉴스는 하루 25,000회, 1회 최대 100개, 시작 위치 최대 1,000, 관련도·날짜 정렬이다. 완전한 과거 뉴스 덤프나 변경 이력 API가 아니다. 새 신청은 NCP HUB 애플리케이션의 Client ID/Secret을 사용한다. [FAQ](https://ncloud.com/support/faq/prod/3756?categoryCode2=APP)는 한시 무료 기간의 한도 증설 불가를 안내한다. 무료 기간 종료일·이후 단가는 이번 확인 자료에서 확정하지 못했다.
- [9월 7일 시행 개발자센터 약관 공지](https://developers.naver.com/notice/article/33400)는 검색결과의 임의 가공·AI 입력·학습·평가 사용 등을 제한한다. 원본 보관 원칙과 충돌하므로 우리 파이프라인의 LLM 입력으로 제안하지 않는다. NCP에는 [9월 20일 시행 예정 공지](https://www.ncloud.com/support/notice/all/2243)도 있으나 본문을 완전히 확보하지 못했으므로 별도 약관 검토 전 적합하다고 판단하지 않는다.
- 이 조사에서 사용한 웹 검색 도구와 네이버 API 실호출은 다르다. 네이버 키 발급·호출은 하지 않았다. 검색 순위·제목 조각 자체를 출시 정답으로 사용하지 않았다.

## 대안과 AI 추천

| 방향 | 원래 우려를 해결하는 범위 | 남는 누락·효과 한계 | 운영·복잡도 | 학습 가치 |
|---|---|---|---|---|
| 카탈로그 개선 | 수집 실패·범위·중복·이력을 개선하면 새 발견 신뢰성이 좋아질 수 있음 | 공식 출시 의미·카탈로그 밖 제품은 계속 부족. 이번 CU 반례 외 개선율 미측정 | 기존 운영 경로 활용, 소스별 완전성 검증 필요 | 파싱 계약·정합성·실패 복구 |
| 적합한 공개 API로 일부 대체 | 포장식품 제조·표시 정보를 구조화해 확보할 가능성. 푸드QR은 직접 바코드 조건 제공 | C005 중단, I1250 행정자료, QR/HACCP 등록 범위 제한. 매장 메뉴·출시일 대체 불가. 실제 일치율 미측정 | 키·약관·갱신 지연·다대다 연결·증분 한도 관리. 전면 대체를 정당화할 근거 부족 | 외부 API 계약·식별자 연결·증분 복구 |

AI 추천은 **결합을 최종 확정하는 것이 아니라 공식 발표 연결을 첫 격리 구현 단위로 검증**하는 것이다. 포장식품 API는 푸드QR 바코드 조회→HACCP 이름 후보의 순서로 키 확보 후 소표본을 대조한다. C005 운영 도입·GS1 유료 계약·검색결과의 LLM 입력은 지금 추천하지 않는다.
기존 카탈로그 유지 역시 영구 결정이 아니다. 같은 기간의 공식 출시 목록을 먼저 만들고 각 수집 경로가 무엇을 놓치는지 확인한 뒤 소스별 대체 여부를 정한다.

## 방향 선택 후 가장 작은 수직 구현안

사용자가 이 격리 실험을 선택했고 아래 범위를 구현·검증했다. 운영 파이프라인 연결은 포함하지 않는다.

1. 입력: 격리된 W35/W36 카탈로그와 이미 읽은 공식 발표 1개. 원문은 비공개 임시 경로에만 둔다.
2. 발표 관측에는 URL·확인시각·게시일, 출시 주장에는 제품명·브랜드·사건 종류·본문 시점을 별도로 남긴다. 기사와 상품의 키를 분리한다.
3. 이름·브랜드의 정확 일치도 ‘연결 후보’일 뿐이다. SKU/온도/포장 차이, 재출시 여부, 날짜 누락이면 자동 확정하지 않는다. 사용자 승인 없는 시즌 정책을 코드에 넣지 않는다.
4. 출력: 공개 발행 대신 비교 JSON. 기존 상품 ID·URL 그대로, 판정 근거와 보류 사유 포함. 재실행 결과 일치·입력 변경 검출·잘못 연결된 변형 보류를 확인한다.
5. 완료 조건: 신규·복귀의 차이와 아이스 변형·프로모션·동명 타 채널 반례를 보존한다. LLM을 넣으면 수동 해석을 정답 후보로 분리해 별도 평가한다. 공개 API 실조회 전에는 응답을 꾸며 넣지 않는다.
6. 되돌리기: 연구 전용 스크립트와 임시 결과만 제거한다. `pipeline/`, 수집 소스 표, 공개 weeks, ID·URL은 변경하지 않는다.

후속 **운영 도입** 전에 필요한 규칙 수정안: ADR-0016에 ‘보도자료를 전체 제품 카탈로그로 취급하는 안의 기각은 유지하되, 기존 상품에 출시 사실을 연결하는 별도 근거 경로는 검증 후 허용’이라는 범위를 제안한다. AGENTS.md에는 ‘출시 근거는 관측 목록과 분리하고 게시일·행정일·유효일을 출시일로 대체하지 않으며 승인된 소스만 사용한다’를 추가하는 안이다. 현재 ADR-0018의 후속 검증 범위 안인 오프라인 실험에는 운영 규칙을 바꾸지 않는다.

### 구현 결과와 재현

[연결 실험 코드](https://github.com/aeginventor/this-week-taste/blob/10865a188e631a4810dfe223ce9b98f488e31aa2/scripts/link_launch_evidence.py) · [의미 경계 회귀 테스트](https://github.com/aeginventor/this-week-taste/blob/10865a188e631a4810dfe223ce9b98f488e31aa2/tests/test_launch_evidence_experiment.py)

AI가 공식 본문을 읽어 4개의 주장을 분리했다. 자동 추출이나 사용자 작성 정답으로 표시하지 않았다.
관측 문서의 URL·게시일·확인일·SHA-256과 주장별 사건 종류·본문 날짜·판매 맥락을 보관했다.
전체 4개 소스의 W36 카탈로그 **4,528항목을 이름 중복 검사 문맥**으로 사용하고 선택한 8항목만 출력했다. 8항목만으로 이름이 유일하다고 가정하지 않았다.

- 호지 라떼: 신규 출시의 정확 이름 후보. 블랙 라떼: 시즌 복귀의 정확 이름 후보. 기사에 카탈로그 키가 없으므로 둘 모두 SKU 확인으로 승격하지 않았다.
- 아이스 변형: 변형 식별 미확인. 퓨어 호지차: 명시적 출시 사건 없음. 교촌 팝콘: 판매 맥락 다름. 각각 보류했다.
- CU 2건·피자헛: 이번 발표 표본에서 근거 없음. API 응답이나 출시일을 채워 넣지 않았다.
- 같은 입력 두 번 실행의 출력 SHA-256은 `dce4073cdf8c53b17bf5f19418ca3c8e34fd67bb1c3ac6226827ad22ae040251`로 같았다. 문서 변경을 거부하는 테스트와 브랜드·이름 중복·게시일 오인·시즌 정책 미결정 보존을 검증했다.
- 공개 출시 상태 생성·발행은 0건이다. 테스트 성공은 자동 근거 추출이나 운영 출시 정확도의 입증이 아니다.
