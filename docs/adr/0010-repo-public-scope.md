# ADR-0010 공개 저장소에는 발행물만 둔다

상태  채택
날짜  2026-08-24

## 맥락

저장소는 공개다. 포트폴리오를 겸하므로(1장) 그건 유지해야 한다.

그런데 `.gitignore`가 이렇게 정해두고 있었다.

> `data/` 는 커밋한다. JSON 파일이 곧 데이터베이스이고 git 히스토리가 곧 아카이브다

이유가 둘 있었고 둘 다 타당했다. [ADR-0003](0003-storage-boundary.md)이 DB를 안 두기로 해서
데이터를 둘 곳이 파일뿐이었고, `web/lib/weeks.ts`가 `data/weeks/`를 **파일로 직접 읽어**
정적 사이트를 만든다(`docs/DEPLOY.md`가 "데이터가 저장소에 있으므로 `git push` →
호스트 재빌드로 끝"이라고 설계했다).

**놓친 것은 저장소가 공개라는 사실이다.** 그래서 이런 것이 올라가 있었다.

| | 크기 | 내용 |
|---|---|---|
| `data/raw/` | 13MB | 소스 사이트의 **응답 원본 그대로** |
| `data/snapshots/` | 4.4MB | CU 5,082 + 홈플러스 2,966건 — **전체 카탈로그** |

7장은 *"소스 사이트의 데이터를 통째로 재배포하는 형태의 페이지"*를 금지한다.
**공개 저장소도 배포다.** 규칙이 페이지만 보고 저장소를 안 봤다.

## 결정

**저장소를 둘로 나눈다.**

| | 무엇 |
|---|---|
| `this-week-taste` (공개) | 코드 + `data/weeks/` 발행물 |
| `this-week-taste-data` (비공개) | `raw/`, `snapshots/`, `diffs/`, `enriched/` |

발행물만 공개하는 근거는 그것이 **요약 + 원문 링크**라 7장이 애초에 허용한 형태이기 때문이다.

경로는 `pipeline/paths.py` 한 곳이 정하고 `THIS_WEEK_TASTE_DATA_DIR`로 저장소 밖을 가리킨다.
`weeks.py`가 날짜의 단일 지점인 것과 같은 이유다 — 같은 경로를 네 파일이 제각기 계산하고
있으면 한 곳을 옮길 때 나머지가 조용히 예전 자리를 본다.

⚠️ **`publish.py`의 `WEEKS_DIR`은 여기 넣지 않는다.** 웹 빌드가
`process.cwd()/../data/weeks`를 상대 경로로 읽어서 옮기면 사이트가 깨진다.

히스토리에서도 지운다(`git filter-repo --path data/ --invert-paths` + 강제 푸시).

## 결과

**얻는 것** — 재배포 문제가 사라진다. `.git`이 4.8MB → 384KB로 줄어 클론이 가벼워진다.
공개 저장소가 "코드와 결과물"만 담게 되어 읽는 사람에게도 명확하다.

**감수하는 것**
- 저장소가 둘이라 관리 지점이 늘었다. 주간 자동화를 붙일 때 양쪽을 다뤄야 한다
- `data/` 만 담았던 커밋 3개가 히스토리에서 사라졌다. 내용 없이 "스냅샷 추가"라고 적힌
  빈 커밋으로 남기는 것보다 낫다고 판단했다 — 그건 거짓말이 된다
- 강제 푸시는 완전하지 않다. 고아 객체가 잠시 남을 수 있고, 열흘쯤 공개돼 있었다

**커밋 이메일은 그대로 둔다.** 공개 히스토리에 개인 주소가 남지만, 실질 위험은
User-Agent 쪽이다 — 거기에 같은 주소를 쓰면 크롤링당한 회사가 **자기 서버 로그만으로**
운영자를 특정할 수 있게 된다. 그 경로는 UA에서 끊는다(7장 "실행 전에 승인을 받는 것").
`/about`을 통해 저장소로 이어지는 것은 포트폴리오라서 **의도한 연결**이다.

## 버린 대안

**저장소를 비공개로 전환** — 제일 안전하다. 하지만 포트폴리오라 공개가 목적이고,
한 번 공개한 것을 되돌리는 것보다 **무엇을 공개하는지 고르는 것**이 맞는 해법이었다.

**`data/raw/`만 제외** — 13MB가 빠져 용량 문제는 풀린다. 그러나 카탈로그 8천 건은
그대로 공개된다. 재배포의 핵심은 원본 HTML이 아니라 카탈로그다.

**GitHub Actions artifacts에 스냅샷 보관** — 저장소를 안 늘린다. 90일 보존도 diff에는 충분하다.
하지만 "git 히스토리가 곧 아카이브"라는 ADR-0003의 성질을 잃고, 로컬과 CI 사이
손바뀜이 번거로워진다.

**오브젝트 스토리지(R2/S3)** — 실무에서 가장 정석이고 용량 걱정이 없다.
새 서비스 가입과 키 관리, 그리고 파이프라인에 업로드/다운로드 코드가 는다.
저장소 하나 더 만드는 쪽이 지금 단계에서 더 싸다.
