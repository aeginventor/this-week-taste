# ADR-0015 단종을 발행하지 않고 오탐 지표로 쓴다

상태  채택
날짜  2026-08-26

## 맥락

4장 스키마는 발행 항목에 `status: "active" | "discontinued"`를 두고 있었고,
`publish.py`가 이렇게 채웠다.

```python
for removed in result["removed"]:
    previous = previous_by_external.get(removed["external_id"])
    if not previous:
        continue  # 지난주에 발행되지 않았던 항목
    items.append({**previous, "week": week, "status": "discontinued"})
```

사이트는 이것을 "단종 후보" 섹션으로 그렸다. W35가 첫 발행이라 `discontinued: 0`이었고,
W36(2026-08-31)이 이 경로가 처음 도는 주였다.

### 정확도가 근거보다 약하다

사람이 먼저 지적한 것은 정확도였다 — **지점마다 재고가 다르고, 목록에서 빠지는 것이
곧 단종은 아니다.** 문서도 이미 반쯤 인정하고 있었다.

- 2.1은 "지난주에만 있는 항목 → **단종 후보**"라고 쓰는데 4장은 `discontinued`로 **단정**한다.
  후보를 확정으로 승격시키는 자리가 발행 단계였다
- `targets.yml`은 소스를 유형으로 나눠뒀다. `catalog: partial`(GS25·세븐일레븐·이마트24)은
  **"차집합이되 목록 진입/이탈이지 신상/단종이 아니다"**. 세븐일레븐은 목록의 91%가
  월간 행사라 아예 보류됐다
- 2026-08-24 실측에서 `added` 오탐 4건이 **전부 재입고**였다. `gd_idx`가 14147~16341로
  지난주 최댓값(27989)보다 한참 낮은 오래된 상품들이 목록에 돌아온 것이다.
  **목록을 들락날락한다는 뜻이고, 그러면 `removed`도 같은 성질이다**

### 그런데 코드를 읽어 보니 재는 대상 자체가 달랐다

`previous_by_external`는 `load_week(previous_week)` — 지난주 **발행본**이다.
스냅샷이 아니다. `if not previous: continue`가 나머지를 전부 거른다.

그래서 `discontinued`가 실제로 뜻한 것은 **"우리가 지난주에 신상이라고 실은 것이
이번 주 목록에서 사라졌다"**였다. 카탈로그에서 사라진 모든 것이 아니다.

이 사실은 CLAUDE.md 11장에도 잘못 적혀 있었다 — "W36. **CU만 431건이 대기 중이다**".
그 431건은 W33→W35 diff의 `removed`인데 W35가 첫 발행이라 하나도 발행된 적이 없다.
실제 모수는 W35 발행본 211건(homeplus 110 / cu 91 / starbucks 9 / orion 1)이다.

### 모수를 알고 나니 의미가 뒤집힌다

**일주일 만에 진짜로 단종되는 제품은 드물다.** 우리가 신상이라고 실은 지 일주일 만에
목록에서 사라졌다면 훨씬 그럴듯한 설명은 이것들이다.

- 애초에 행사 상품이었다
- 한정 수량이 소진됐다
- **지난주 `added`가 오탐이었다** — 재입고를 신상으로 잡았다

즉 이 값은 제품 상태가 아니라 **우리 판정의 채점표**다. 그것을 제품 상태인 척
발행하고 있었다.

## 결정

**`status` 필드를 4장 스키마에서 없애고, 같은 계산을 발행 리포트의 오탐 지표로 옮긴다.**

`data/weeks/<week>.report.json`의 `by_source.<소스>.published_then_gone`:

```jsonc
{
  "previous_published": 91,          // 모수 — 지난주 그 소스의 발행 건수
  "gone": 3,                         // 그중 이번 주 목록에서 사라진 것
  "names": ["...", "...", "..."]     // 건수만으로는 판단이 안 된다
}
```

CLAUDE.md 8장이 이미 오탐 지표를 둘 갖고 있고, 이것이 셋째다.

| 지표 | 필요한 것 |
|---|---|
| `source_new_label.added_not_labelled` | 소스의 NEW 라벨 |
| `monotonic_id.added_below_previous_max` | 단조 증가 키 |
| **`published_then_gone.gone`** | **없음 — 모든 소스에서 성립한다** |

**지난주 발행본이 없으면 키를 아예 싣지 않는다.** 0을 실으면 "사라진 것이 없다"로
읽히는데 사실은 "잴 수 없었다"이다. `monotonic_id`를 조건부로 싣는 것과 같은 이유다(7장).

반대로 **모수가 있을 때의 0은 싣는다.** "지난주 신상이 하나도 안 사라졌다"는
좋은 소식이지 미계산이 아니다.

`diff.py`의 `removed` 계산은 **그대로 둔다.** 보여주려고가 아니라 `added`를 거르려고
센다 — `diff.py:150-154`에서 `unmatched_previous`가 L4 유사도 짝짓기의 입력이고,
그게 없으면 이름이 바뀐 제품이 전부 신상으로 들어온다(2.1이 막으려는 바로 그것).

## 결과

**얻는 것.** 채점 불가였던 소스가 처음으로 채점된다. 지금 상황은 이랬다.

| 소스 | 라벨 | 단조 키 | 지금까지 |
|---|---|---|---|
| cu | ✅ | ✅ | 채점 가능 |
| pizzahut | △ | ✅ | 채점 가능 |
| **homeplus** | ❌ | ❌ | **채점 불가 — 발행물의 절반인데** |
| starbucks·compose·kyochon·mcdonalds·parisbaguette | ❌ | ❌ | 채점 불가 |

홈플러스는 W35 발행 211건 중 110건으로 최대 소스인데 오탐률을 잴 방법이 없었다.
3단계 판단이 CU 하나에 기대고 있던 가장 큰 구멍이 여기였다.

**틀린 정보를 안 싣는다.** `catalog: partial` 소스에서 "단종"은 특히 거짓말에 가깝다.

**답이 데이터로 온다.** 몇 주 돌리면 "지난주 신상의 몇 %가 사라지는가"를 알게 된다.
거의 0%면 사라지는 몇 건은 진짜 단종일 수 있어 그때 실을지 다시 판단하면 되고,
높으면 `added`에 문제가 있다는 뜻이라 애초에 발행하면 안 될 것이었다.
**어느 쪽이든 지금 안 싣는 쪽이 안전하다.**

**감수하는 것.** "이번 주 사라진 제품"을 방문자가 볼 수 없다. 정보 가치가 없지는
않지만, 정확도가 뒷받침되지 않는 상태로 싣는 것보다는 낫다.

**되돌릴 수 있다.** `diffs/`는 비공개 저장소에 영구히 남으므로 나중에 마음이 바뀌면
과거 주차를 다시 계산할 수 있다. 잃는 데이터가 없다.

## 버린 대안

**발행물에는 남기되 사이트에서만 감춘다.** 데이터를 쌓아두고 UI 결정을 미루는 안.
버린 이유는 **쓰지 않는 필드가 낡는 게 아니라 거짓말이 되기 때문이다.**
7장이 그 사례를 갖고 있다 — `publish.py` docstring이 id를 "바코드가 있으면 바코드"라고
설명하고 있었는데 ADR-0001이 그 결정을 뒤집은 뒤에도 그대로였다. 그리고 이 안은
`status` 필드를 파이프라인 전체가 계속 지고 가게 한다.

**이름만 정직하게 바꾼다** (`discontinued` → `gone_from_list` 같은 것).
버린 이유는 이름을 고쳐도 **발행할 값어치가 생기지 않기 때문이다.** 방문자에게
"목록에서 사라졌으나 단종인지는 모릅니다"라고 알리는 것은 우리 사정이지 그들의
관심사가 아니다. ADR-0013에서 `source_url_kind`를 버린 것과 같은 이유다.

**그대로 두고 W36에서 결과를 본다.** 모수가 431이 아니라 211이니 생각보다 적을 수
있다는 관찰은 맞다. 버린 이유는 **한 주 동안 틀린 정보가 실제로 사이트에 실리기
때문이다.** 지표로 옮기면 같은 관찰을 하면서 발행은 안 한다 — 관찰 비용이 같은데
위험만 없다.

**`removed` 계산도 같이 없앤다.** 발행을 안 할 거면 계산도 필요 없어 보인다.
버린 이유는 2.1이 그것을 요구하기 때문이다. `removed` 목록은 L4 매칭의 입력이라
없으면 이름이 한 글자 바뀐 제품이 "단종 1건 + 신상 1건"으로 갈라진다.
2026-08-24 실측에서 홈플러스 `review`가 4건 나왔는데, 그것들이 전부 `added`로
들어갈 뻔한 것들이었다.
