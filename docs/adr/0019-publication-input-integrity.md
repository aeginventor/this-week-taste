# ADR-0019 발행 입력의 지문으로 같은 주의 이전 성공본을 검증한다

상태  채택
날짜  2026-09-09

2026-09-10 보완: [ADR-0020](0020-new-products-and-upcoming.md)에 따라 수집 시점·실패·검증 상태는 내부 리포트에서 관리한다. 화면에 일괄 표시하지 않으며 입력 검증 자체는 유지한다.

## 맥락

격리된 합성 사례에서 이번 diff를 baseline으로 바꿔 publish가 None을 반환해도
merge는 이전 부분 파일을 포함했다. 또한 W30 관측을 W36까지 이월하고 W37에
복구하면 실제 공백 7주가 gap_weeks=1로 보고됐다. 실제 운영에서 같은 형태의
오발행이 있었는지는 확인되지 않았다.

## 사용자 결정

같은 주의 이전 성공 결과는 원본·판별 근거가 그대로임을 검증할 수 있을 때만
수집 시점을 밝혀 유지한다. 다른 소스는 계속 발행한다. 과거 주차의 데이터를
이번 주 새 발견으로 반복 발행하지 않는다.

## 구현 계약

- 비교·건수 검증은 최근 실제 성공 스냅샷을 찾는다. 이월 파일은 성공 관측이 아니다.
  기존 최대 4주의 부재 비교 한도는 실제 성공 주차에 적용한다.
- 이월에 사용할 마지막 데이터는 별도로 찾을 수 있지만 그 날짜를 새 관측으로 바꾸지 않는다.
- diff는 사용한 관측·원본 아카이브·관련 코드의 SHA-256과 결과의 지문을 기록한다.
  처리 전후 입력이 달라지면 결과를 쓰지 않는다. 보강에서 새로 생긴 원본은 허용하되
  diff 시점에 이미 있던 원본의 변경·소실은 허용하지 않는다. 원본과 스냅샷의 역사적
  연결까지 소급 증명하는 것은 아니며, 지문을 기록한 시점 이후의 변경을 검출한다.
- 보강 결과는 사용한 diff와 연결한다. 연결을 검증할 수 없는 옛 보강 파일은 경고 후
  설명·태그 입력에서 제외한다. 보강 재실행 또는 검증된 원본 재처리로 복구한다.
- 부분 발행물은 관측, diff, 보강 결과, 코드의 지문과 자신 내용의 지문을 기록한다.
- 병합은 주차·소스·스키마·지문을 확인한다. 기준선 변경, 입력 누락, 내용 변경,
  코드 변경, 손상된 JSON, 증명이 없는 옛 부분 파일은 현재 병합에서 제외한다.
- 제외한 부분 파일은 삭제하지 않고 소스별 상태와 이유를 병합 결과에 남긴다.
  과거 공개 발행 파일은 그대로 읽을 수 있다. 옛 부분 파일은 diff부터 재생하면 새 증명을 얻는다.
- 검증된 이전 결과의 수집·생성 시점을 공개 결과에 포함한다.
- 모든 부분이 부적합하면 조용히 성공하지 않고 실패한다. 기존 공개 파일은 보존한다.
- 각 JSON은 임시 파일을 완성한 뒤 원자적으로 교체한다. 주간 JSON을 발행의 기준으로
  삼고 리포트에는 같은 generation_id를 남겨 둘의 불일치를 감지한다.
- Makefile은 병합 실패를 성공 종료로 덮지 않는다.

## 대안과 비용

이번 실행 성공분만 사용하는 안은 단순하지만 일시 장애에도 검증된 같은 주 결과가
빠진다. 기존 파일을 무조건 쓰는 안은 조용한 혼합을 남긴다. 사용자 결정에 따라
검증 가능한 이전 결과를 사용한다. 해시 계산과 재생 비용이 추가된다.

파일별 원자 교체는 여러 파일을 한꺼번에 교체하는 트랜잭션이 아니다. 주간 JSON에
항목·소스 상태를 함께 담아 웹은 하나만 읽고, 별도 리포트의 generation_id는 교차 확인한다.
DB나 실행별 저장소로 전면 이전할 필요성은 아직 측정하지 않았다.

해시는 출시의 진실성·파서의 정확성·원본 보존의 적법성을 증명하지 않는다.
입력 파일을 전부 읽는 비용, 다중 프로세스 동시 실행, 장기간 데이터 보관은 별도로 측정한다.

## 대체 범위

ADR-0007의 4주 한도는 유지하며 이월 파일의 주차를 성공 시점으로 보는 해석을 수정한다.
ADR-0008의 소스별 부분/병합 형식을 유지하며 무조건적인 파일 포함을 대체한다.
ADR-0011의 주차당 스냅샷 재사용과 정상 스냅샷 보존은 유지한다.
