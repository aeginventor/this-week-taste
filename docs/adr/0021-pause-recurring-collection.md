# ADR-0021 복구를 확인하지 못한 주간 수집을 중단한다

상태 채택
날짜 2026-09-28

## 맥락

사용자는 반복 수집 실패를 해결하고, 해결할 수 없으면 주기적 수집을 중단하라고 지시했다.
W37~W39 실행은 같은 main `543dbff`를 사용했다. 작업 브랜치의 소스별 실행 환경 분리는
아직 main에 반영되지 않았다. 개선안의 존재를 운영 장애 해결로 보고할 수 없다.

최근 W39 [일반 수집](https://github.com/aeginventor/this-week-taste/actions/runs/35566246858)은
14개 소스의 실제 W39 스냅샷·diff와 원본을 비공개 main `c5b5d5f`에 저장했지만,
컴포즈(403), 맘스터치(robots 연결 시간 초과), 파리바게뜨(robots 경로 금지),
홈플러스(카테고리 건수 이상)는 실패했다. 홈플러스는 W35 자료를 이월했다.
[GS25 수집](https://github.com/aeginventor/this-week-taste/actions/runs/35588657544)은
기존 목록에서 CSRF 토큰을 찾지 못했다. 차단 우회나 실패 무시는 해결책이 아니다.

2026-09-28 W40에 기존 홈플러스 경로를 1초 간격·기존 UA·robots 준수로 작게 확인했다.
디저트빵은 HTTP 200·SUCCESS지만 `totalCount=0`, 우유는 48건, 과자/쿠키/파이는
총 233건 중 첫 페이지 100건이었다. 분류표 응답에도 세 코드가 나타났다.
파서가 응답의 상품을 빠뜨린 증거는 없으며, 0건이 실제 품절인지 카탈로그 의미 변경인지는
확정하지 못했다. 3개 카테고리 표본을 전체 수집 성공으로 세지 않았다.

## 결정

- GitHub `weekly` 전체를 비활성화한다. 현재 main을 그대로 반복 실행하지 않는다.
- 기존 스냅샷·원본·발행물·코드·준비된 수정은 보존한다. 브랜드를 서비스 범위에서 제외하지 않는다.
- 카테고리 감소 검사나 robots 판정을 낮춰 성공으로 만들지 않는다.
- main 반영·사이트 배포로 미승인 변경 전체를 운영에 넣지 않는다.
- 모니터링은 의도한 중단을 누락으로 알리지 않고 예기치 않은 재개를 감지한다.

사용자가 정한 것은 해결되지 않은 반복 수집의 중단이다. AI는 로그·원격 파일·제한된
실제 응답을 대조하고 현재 전체 예약 작업을 안전하게 복구했다고 볼 수 없다고 판단했다.

## 결과와 재개 조건

2026-09-28 11:57 KST에 workflow 상태 `disabled_manually`, 실행·대기 작업 0건을 확인했다.
정상 동작하던 14개 소스도 예약 수집이 멈춘다는 비용을 감수한다. GitHub 설정에서 중단했으므로
저장소의 cron 정의가 남아 있다는 이유로 자동화가 동작한다고 해석하지 않는다.

재개하려면 실행 가능한 소스의 묶음과 중단할 경로를 확정하고, 홈플러스 관측 범위 또는
제외 사유를 명시한다. 사용자 승인된 운영 변경 범위로 실제 러너 수집·소스별 관측 주차·
비공개 데이터 push를 검증한 뒤 예약 실행을 활성화한다. 기존 브랜치 전체 병합이나 사이트
배포를 수집 재개의 자동 전제로 삼지 않는다. 일회 수집은 기존 접근·보관 원칙을 따른다.

## 버린 대안

- 같은 경로를 매주 재시도하며 같은 알림만 보내기: 사용자 요청을 해결하지 못한다.
- 오래된 카테고리 기준을 낮추거나 빈 카테고리를 빼기: 완전성을 확인하지 않고 정상화할 위험이 있다.
- 로컬 성공을 GitHub 성공으로 간주하기: ADR-0017에서 이미 서로 다른 응답을 확인했다.
- 준비된 브랜치 전체를 즉시 main에 반영하기: 미승인 발행안·화면 변경과 배포까지 포함한다.
