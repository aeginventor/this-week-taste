작성 2026-08-11 (수직 관통 직후). **되돌리는 비용이 시간이 갈수록 커지는 순서**로 적었다.
아직 커밋이 하나도 없어서 지금은 전부 공짜에 가깝다.

## 이미 되돌렸다

### 1. 제품 ID: 바코드 → gdIdx ✅ 적용됨

승인된 계획은 `id = cu--<바코드>`였다. 전 카탈로그를 뜨자 `snapshot.py`의 유일성 검사가 걸렸다:

- gdIdx 5,082건 중 **중복 0건**
- 바코드 **16건 중복**(32항목). 가격이 다른 경우까지 있다 —
  `풀무원)나주식수육곰탕`이 8,000원(gd=20181)과 9,900원(gd=24447)으로 두 번 등록돼 있다

바코드는 *물리적 제품*을, gdIdx는 *카탈로그 항목*을 가리킨다. 발행 단위는 카탈로그 항목이고
저 둘은 따로 보여줘야 하므로, 바코드를 id로 쓰면 하나가 조용히 사라진다.
바코드는 `alt_ids`에 남아 diff의 1순위 매칭 키로 계속 쓰이므로 **편의점 4사 교차 대조는 그대로 가능하다.**

> 되돌리고 싶다면: 지금이 가장 싸다(발행물 1개). 단 충돌 16건의 처리 규칙을 먼저 정해야 한다.
> 아카이브 URL이 id에 묶이므로 발행이 몇 주 쌓이면 되돌리기 어려워진다.

### 2. 카테고리 건수 검증: 고정 기준 → 직전 주 기준 ✅ 적용됨

정찰 실측치(2026-08-11)를 매주 ±10% 기준으로 쓰고 있었다. 카탈로그는 정상적으로 변하므로
**시간이 지나면 반드시 오탐이 나서 조용히 발행이 멈춘다.** 오늘 이미 어긋나기 시작했다
(간편식사 204/208, 과자류 1146/1154).

이제 직전 주 스냅샷이 있으면 그쪽을 기준으로 30%~300%를 보고, 첫 수집일 때만 정찰 실측치
±10%를 쓴다. 첫 수집의 빡빡한 기준은 스크래퍼 검증용이고, 그 뒤의 느슨한 기준은
구조 붕괴 감지용이다 — 목적이 다르니 기준도 달라야 한다.

## 되돌려야 하는데 아직 안 한 것

### 3. 합성 주차 데이터가 `data/`에 있다 ⚠️ **진짜 2주차 수집 전에 반드시 지울 것**

```
data/snapshots/2026-W32/        ← 합성 (W33에서 gdIdx 상위 30건 제외)
data/weeks/2026-W33.json        ← 위 합성물에서 파생된 발행물
data/weeks/2026-W33.report.json
data/diffs/2026-W33/
data/enriched/2026-W33/
```

`data/`는 CLAUDE.md 2.2에 따르면 **데이터베이스이고 git 히스토리가 아카이브**다.
거기에 합성 데이터가 섞이면 아카이브가 오염된다. `snapshots/2026-W32/cu.json`에는
`synthetic_note`가 있지만 **발행물에는 전파되지 않았다** — `weeks/2026-W33.json`만 보면
진짜인지 합성인지 알 수 없다.

- **`data/snapshots/2026-W33/`(진짜, 실제 수집)은 남긴다.** 다음 주 수집 때 이게 '지난주'가 되어
  진짜 2주 검증이 성립한다.
- 나머지 5개 경로는 배포 확인이 끝나면 지운다:
  ```
  rm -rf data/snapshots/2026-W32 data/diffs/2026-W33 data/enriched/2026-W33 \
         data/weeks/2026-W33.json data/weeks/2026-W33.report.json
  ```
- 지우기 전에 커밋하지 말 것. 커밋하면 히스토리에 영구히 남는다.

### 4. `alert.py`의 GitHub Issue 생성 코드

8장 5단계(자동화)는 아직 범위 밖인데 GitHub API를 치는 코드를 미리 썼다.

- 지운다면: `notify()`를 로그만 남기게 줄이고 20줄쯤 삭제
- 남긴다면: 5단계에서 실제로 돌려보기 전까지 "동작한다"고 가정하지 않는다

판단: **남겨도 된다.** 작고 격리돼 있고, 5단계가 멀지 않다. 다만 CLAUDE.md 11장에
미검증으로 명시했다.

## 되돌리지 않되 알고 있어야 하는 것

### 5. `curate.py` 100줄이 한 번도 실행되지 않았다

API 키가 없어 폴백 경로만 탔다. 배치 처리, 재시도, 스키마 검증, 이름 불변 검사 —
전부 미검증이다. **이게 현재 가장 큰 단일 리스크다.** 키가 생기면 가장 먼저 돌려볼 것.

지금 지우고 나중에 다시 쓰는 것도 방법이지만, 6장이 규정한 규칙(이름 불변, 근거 없는
blurb 금지)을 코드로 옮겨둔 값이 있어서 남기는 쪽이 낫다고 판단했다.

### 6. `curate.py`의 카테고리 17종이 편의점 기준이다

`도시락, 김밥, 삼각김밥, …` 은 CU를 보고 만든 목록이다. 카페·프랜차이즈를 붙이면
맞지 않는다. 4단계에서 채널별로 분리하거나 소스에서 받아오는 쪽으로 바꿔야 한다.
지금 일반화하는 것은 7장 위반이므로 하지 않았다.

### 7. `web/lib/weeks.ts`가 `process.cwd() + "../data/weeks"`를 읽는다

빌드 타임에만 쓰이지만 배포 환경에서 작업 디렉토리가 다르면 깨진다.
Vercel 등에서 Root Directory를 `web`으로 잡으면 `..`가 저장소 루트가 되어 동작하지만,
**저장소 전체가 배포 대상에 포함돼야 한다.** 배포 설정에서 확인할 것.

### 8. 이미지가 CU CDN에서 직접 로드된다

CLAUDE.md 7장이 이미지 복제 저장을 금지하므로 원본 URL을 참조한다. 이는 의도된 것이지만
공개 배포하면 **CU의 CDN에 우리 트래픽이 붙는다.** CDN 호스트명이 난수 문자열이라
언제든 바뀔 수 있고(정찰에서 확인), 핫링크가 차단될 수도 있다.
깨진 이미지가 조용히 늘어나는 것을 감지할 장치가 아직 없다.
