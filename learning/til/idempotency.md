# 멱등성 (idempotency)

**같은 작업을 여러 번 해도 결과가 한 번 한 것과 같은 성질.**

## 문제 상황

이 프로젝트는 수집과 발행이 **다른 사람(?)이 다른 시각에** 돌린다.

```
월요일 10:00   GitHub Actions 봇이 수집 (스냅샷 → diff)
그 뒤 아무 때   사람이 로컬에서 발행 (enrich → curate → publish)
```

나뉜 이유는 `curate.py`가 `claude -p`(구독 인증)로 도는데 CI에서는 안 되기 때문이다.
자동 발행하면 전량이 `blurb` 없이 나간다.

그런데 2026-W35에 실제로 이런 일이 있었다.

```
14:24  사람이 발행
15:30  봇이 다시 수집  ← 발행이 근거로 삼은 스냅샷이 조용히 교체됐다
```

그때는 차이가 0이라 무해했다. **하지만 그 사이 소스 카탈로그가 바뀌었다면,
발행물은 이미 없는 스냅샷을 근거로 삼은 게 된다.** 어디에도 흔적이 안 남는다.

## 무엇이 멱등이 아니었나

`snapshot.take()`가 부를 때마다 새로 긁고 덮어썼다. 두 번 부르면 결과가 다르다.

**HTTP로 비유하면 `GET`이어야 할 것이 `POST`처럼 굴었다.**
- `GET /snapshots/2026-W35/cu` — 몇 번을 불러도 같은 것이 나와야 한다
- `POST` — 부를 때마다 새 자원이 생긴다

## 어떻게 고쳤나 (`ADR-0011`)

**"한 주차의 스냅샷은 한 번만 뜬다."** 이미 있으면 다시 긁지 않고 그것을 쓴다.

```python
existing = load_snapshot(week, source_id)
if existing is not None and not refresh:
    log.warning("%s %s 스냅샷이 이미 있다 (%s, %d건) — 다시 긁지 않는다. "
                "덮어쓰려면 --refresh (ADR-0011).", ...)
    return snapshot_path(week, source_id)
```

여기서 배운 게 셋이다.

**① 건너뛴 것을 시끄럽게 알린다.** 조용히 건너뛰면 사람이 "다시 긁었다"고 오해한다.
그건 2.4가 말하는 조용한 실패다. `log.warning`으로 건수와 수집 시각까지 찍는다.

**② 예외를 두 곳에 남긴다.**

- `--refresh` — 일부러 다시 뜰 때. 명시적이어야 한다
- **이월본(`held_from`)은 재사용하지 않는다** — 이월은 "이번 주 데이터가 없다"는
  뜻이라, 그걸 굳히면 지난주 카탈로그가 이번 주의 최종 스냅샷이 된다

**③ 무엇을 보고 발행했는지 기록한다.** 발행 리포트의 `by_source.<소스>.snapshot`에
스냅샷의 수집 시각과 건수를 남긴다. **멱등이 어긋남을 막고, 이 값이 못 막은 어긋남을
보이게 한다.**

## 곁가지로 배운 것 — 멱등 보정이 다른 걸 깨뜨렸다

`--refresh`를 넣고 나니 새 버그가 생겼다. `--refresh`로 다시 뜨다가 이상 상황
(건수 급감 등)에 걸리면 `_hold_previous()`가 이번 주 파일을 **무조건 덮어썼다.**

즉 검증을 통과했던 이번 주 스냅샷이 지난주 것으로 되돌아갔다. 흔적은 `held_from`
하나뿐이라 조용하다.

```python
existing = load_snapshot(week, source_id)
if existing is not None and not existing.get("held_from"):
    log.warning("이미 정상 스냅샷이 있다 — 이월하지 않고 그것을 유지한다.")
    return True
```

**이월의 목적은 "이번 주 데이터가 없는 자리를 채우는 것"이지 덮어쓰는 게 아니다.**
멱등을 도입하면 "이미 있는 경우"라는 상태가 새로 생기고, 그 상태를 다루는 코드가
전부 재검토 대상이 된다.

## 다른 곳의 멱등

- **HTTP** — `GET`·`PUT`·`DELETE`는 멱등, `POST`는 아니다. `PUT`은 "이 상태로 만들어라"라
  여러 번 해도 같고, `POST`는 "새로 만들어라"라 부를 때마다 늘어난다
- **결제 API** — `Idempotency-Key` 헤더가 표준이다. 네트워크가 끊겨 재시도할 때
  두 번 결제되는 것을 막는다
- **Terraform·Ansible** — "선언한 상태로 수렴한다"가 곧 멱등이다
- **`make`** — 타깃이 최신이면 아무것도 안 한다. 그래서 `make site`를 두 번 쳐도 안전하다

## 이 프로젝트에서

멱등이 필요한 곳과 아닌 곳이 갈린다.

| 단계 | 멱등인가 | 왜 |
|---|---|---|
| `snapshot.py` | ✅ (ADR-0011) | 발행의 **근거**라 바뀌면 안 된다 |
| `diff.py` | ✅ 자연히 | 입력(스냅샷 둘)이 같으면 출력이 같다 |
| `enrich.py` | ⚠️ 아니다 | 매번 상세를 다시 긁는다. 요청이 나가므로 비용이 있다 |
| `curate.py` | ❌ | LLM이라 같은 입력에도 다른 답이 나온다 |
| `publish.py` | ✅ 자연히 | 파일을 통째로 쓴다 |

`curate.py`가 멱등이 아닌 것은 **받아들인다.** 대신 `id`를 `first_seen` 주차에
확정하고 절대 안 바꾸는 것으로 하류를 안정시킨다(4장).

## 한계

- **주차 단위 멱등이지 전역 멱등이 아니다.** 같은 주차를 두 번 뜨지 않을 뿐,
  주차가 바뀌면 당연히 새로 긁는다
- **파일 존재 여부로 판단한다.** 스냅샷이 절반만 쓰이다 중단되면 "있다"로 보인다.
  지금은 그 경우를 막지 않는다 — 실제로 겪은 적이 없어서다(7장의 테스트 기준과 같은 논리)
- **`--refresh`는 사람이 판단해야 한다.** 이미 발행한 주차에 쓰면 근거가 바뀐다
