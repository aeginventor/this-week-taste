# LLM에 식별자를 보내지 말 것

**모델은 문자열을 "값"이 아니라 "의미"로 다룬다. 그래서 키를 왕복시키면 조용히 망가진다.**

## 문제 상황

`curate.py`는 상품 목록을 LLM에 보내 분류와 요약을 받는다. 받은 결과를 원래 항목에
붙이려면 **어느 항목의 답인지** 알아야 한다. 처음엔 당연하다는 듯 상품 키를 그대로 보냈다.

```jsonc
// 보낸 것
{"external_id": "070234705", "name": "사과잼"}
// 받은 것
{"external_id": 70234705, "category": "가공식품/조미료"}   // ← 앞자리 0이 사라졌다
```

홈플러스의 `itemNo`가 **앞자리가 0인 9자리 문자열**이었다. 모델이 그걸 숫자로 해석했다.
JSON 스키마로 `"type": "string"`을 줘도 모델은 `"070234705"`를 "숫자 070234705"로
읽고 정규화해버린다.

## 증상이 없었다

여기가 이 사고의 핵심이다.

`curate.py`는 응답의 키로 원본 항목을 찾는데, 못 찾으면 **그 항목은 LLM 결과를 버리고
원본 그대로 발행한다.** 6장이 "편집 품질보다 발행 자체가 우선"이라고 정해둔 폴백이다.

그래서 이렇게 됐다.

```
홈플러스 20건 중 편집된 것: 0건
발행: 성공
로그: 정상
```

**폴백이 제대로 동작했기 때문에 아무도 몰랐다.** 2026-08-14에 채널별 분류 목록을
검증하다가 "홈플러스만 `기타`가 유독 많네?"에서 우연히 발견했다. 고친 뒤 20/20이 됐다.

## 어떻게 고쳤나

**배치 안에서만 유효한 참조로 바꿨다.**

```python
# 보낼 때:  external_id 대신 r0, r1, r2 …
# 받을 때:  r0 → 원래 external_id 로 우리가 되돌린다
```

`CLAUDE.md` 6장에 규칙으로 올렸다.

> **상품 키(`external_id`)를 LLM에 보내지 않는다.** 배치 안에서만 유효한 참조
> (`r0`, `r1`, …)로 주고받고 우리가 되돌린다.

프롬프트에도 한 줄 넣었다. `- ref는 입력에 있는 문자열을 그대로 돌려준다. 숫자로 바꾸지 마라.`
방어를 두 겹으로 둔 셈인데, **참조 형식 자체가 숫자로 보이지 않는 게 더 근본적인 방어다.**
`r0`은 숫자로 해석할 여지가 없다.

## 같은 성질의 다른 함정들

모델이 "정규화"해버리는 것은 앞자리 0만이 아니다.

| 입력 | 모델이 하기 쉬운 일 |
|---|---|
| `"070234705"` | 숫자로 읽어 앞자리 0 소실 |
| `"8801234567890"` | 큰 정수 → 부동소수점 정밀도 손실 |
| `"1.10"` | `1.1`로 정규화 |
| `"2026-08-25"` | 다른 날짜 포맷으로 재작성 |
| 긴 UUID | 중간 글자를 바꿔 쓴다(환각) |

**공통점은 "그럴듯하게 고친다"는 것이다.** 틀린 값이 아니라 *다른* 값이 오므로
스키마 검증도 통과한다.

## 더 일반화하면

**LLM은 신뢰 경계 밖이다.** 다녀온 값을 그대로 시스템 키로 쓰면 안 된다.
같은 이유로 `curate.py`는 이것들도 지킨다.

- **`name`이 입력과 다르면 그 항목의 LLM 결과를 통째로 버린다.** CU는 제품명을
  12자에서 자르는데, 모델이 그걸 "복원"하면 없는 정보를 지어낸 것이 된다
- **설명문이 없으면 `blurb`는 `null`이다.** 이름만 보고 쓰게 하지 않는다
- **분류는 우리가 준 목록에서만 고른다.** 목록 밖 값이 오면 원본을 쓴다

즉 **LLM에게는 "판단"만 맡기고 "식별"과 "사실"은 우리가 쥔다.**

## 곁가지 — 프롬프트에서 지시의 *자리*가 품질을 바꾼다

같은 파일에서 배운 다른 것. `out_of_scope` 판정을 추가하면서 그걸 프롬프트 1번 자리에
6줄로 넣었더니 **모델이 `name`을 빼먹기 시작했다.** `blurb`가 93건 → 72건으로 떨어졌다.

뒤로 내리고 "다섯 필드를 전부 넣는다"를 명시하니 93건으로 돌아왔다.

지시를 **추가**한 게 아니라 **자리를 옮긴** 것만으로 다른 필드의 품질이 무너진 것이다.
그래서 6장에 경고를 넣었다 — **curate 프롬프트를 건드리면 blurb 건수를 꼭 비교할 것.**

## 한계

- **참조 방식도 완벽하지 않다.** 모델이 `r0`을 빼먹거나 없는 `r99`를 만들 수 있다.
  그래서 응답의 ref가 배치에 없으면 그 항목은 버린다
- **배치 경계를 넘으면 못 쓴다.** `r0`은 그 요청 안에서만 유효하다. 배치 크기(20)를
  바꾸면 참조 번호도 바뀐다
- **근본 해결은 아니다.** LLM이 스키마를 정확히 지키게 만드는 방법(제약 디코딩 등)이
  있지만 `claude -p` 경로에서는 `output_config`를 못 써서 쓰지 못한다
