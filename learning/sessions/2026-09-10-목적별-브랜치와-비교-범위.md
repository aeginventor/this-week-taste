# 커밋을 다시 만들지 않고 작업 브랜치를 정리한다

이미 끝난 한국어 커밋 재구성·중복 판별·발행 입력 검증·기사 실험 동결을 다시 하지 않았다. 이번 사용자 요청에 따라 브랜치 이름을 변경 목적에 맞췄다. 연구 원본과 모델은 다시 실행하지 않았다.

## 현재 확인과 사용자 결정

- 시작은 공개 코드 `bf09907`, 비공개 데이터 `fe8825b`였다. 양쪽 `codex/collection-review`는 원격과 같고 작업 폴더는 깨끗했다. 다른 재설계 작업은 실행 중이 아니었다.
- 현재 AGENTS.md 전체와 커밋 규칙·관련 ADR·최근 기록을 읽었다. 코드 10개·데이터 5개 커밋은 이미 한국어·목적 단위였으므로 SHA와 작성자 정보를 그대로 보존했다. 옛 실험 이력의 영어 제목은 현재 작업 이력으로 다시 합치지 않았다.
- 사용자가 추가로 정한 것은 목적별 브랜치 접두사, 불필요한 작업 도구 이름을 커밋/PR에 넣지 않는 것, 완료한 정리를 반복하지 않는 것이다. 구현·확인은 AI가 수행했다. 기존 커밋의 작성자를 바꾸거나 사용자가 실험 정답을 검수했다고 기록하지 않았다.
- 두 저장소의 시작 refs는 로컬 `scratch/finalize-20260910/recovery/`의 검증된 bundle과 manifest로 보존했다. 비공개 bundle을 공개 Git에 넣지 않았고 무시된 모델·실행 파일·캐시·개인 설정은 추가하지 않았다.

## 브랜치와 실험 이력

양쪽 최종 작업 브랜치는 **`refactor/collection-review`**다. 로컬 이름을 바꾸고 같은 HEAD를 일반 푸시했다. 내용이나 커밋을 바꾸는 강제 푸시는 사용하지 않았다.

| 참조 | 용도 |
|---|---|
| `refactor/collection-review` | 이후 검증된 변경을 커밋·일반 푸시할 작업 브랜치 |
| `archive/redesign-evaluation-20260910` | 원래 실험의 코드 `10865a1`·데이터 `aa31313`을 각각 보존하는 태그. 앞선 연구 커밋과 원래 코드 링크도 계속 도달 가능 |
| 옛 원격 `codex/collection-review` | 이동 전 정리 HEAD. 새 브랜치의 조상이며 삭제 확인 대기 |
| 옛 원격 `codex/redesign-evaluation-20260910` | 보존 태그와 같은 실험 HEAD. 삭제 확인 대기 |

보존 태그는 새 실험 결과가 아니다. 동결 파일·manifest·비공개 freeze 지문은 그대로다. 학습 글에 남아 있던 옛 `tests/test_newsroom_study.py` 링크 한 곳만 실제 보존 위치로 고쳤다. 현재 운영 코드가 과거 모델 결과를 냈다는 뜻으로 링크를 바꾸지 않았다.

## 기본 작업 방식과 반영 제안

사용자의 기존 방식대로 목적별 브랜치에서 완결된 한국어 커밋·일반 푸시를 기본으로 한다. PR은 요청이 있을 때만 만들며 데스크탑 앱을 쓴다는 이유로 추가하지 않는다.
코드와 데이터의 main은 각각 `543dbff`·`a567612`에서 출발한 이력을 fast-forward로 반영하는 안을 제안한다. 데이터 로컬 main `9f22daa`는 원격보다 2개 뒤에 있었으므로 그 차이도 빠뜨리지 않는다. 기존 정리 커밋을 squash하거나 다시 작성할 필요가 없다.

코드 main 푸시는 현재 Vercel 설정상 배포 대상이다. 공개 발행 파일을 바꾸지 않아도 파이프라인·표시 동작은 달라진다. 데이터 main 푸시는 검증/연구 자료와 제외 설정을 반영하며 사이트 배포 트리거는 없다. 두 main 반영, 옛 원격 네 브랜치 삭제, 배포는 각각 사용자의 확인 없이 수행하지 않는다.

같은 날 완료한 Ollama 0.33.3/Qwen 점검은 [기존 기록](../../docs/local-model-audit-2026-09-10.md)을 재사용했다. 수정 버전을 확인하지 못한 취약점을 해결됐다고 바꾸지 않았으며 이번 정리에 추론이 필요하지 않아 모델을 켜지 않았다.
