# 커밋을 다시 만들지 않고 작업 브랜치를 정리한다

이미 끝난 한국어 커밋 재구성·중복 판별·발행 입력 검증·기사 실험 동결을 다시 하지 않았다. 이번 사용자 요청에 따라 브랜치 이름을 변경 목적에 맞췄다. 연구 원본과 모델은 다시 실행하지 않았다.

## 현재 확인과 사용자 결정

- 시작은 공개 코드 `bf09907`, 비공개 데이터 `fe8825b`였다. 양쪽 `codex/collection-review`는 원격과 같고 작업 폴더는 깨끗했다. 다른 재설계 작업은 실행 중이 아니었다.
- 현재 AGENTS.md 전체와 커밋 규칙·관련 ADR·최근 기록을 읽었다. 코드 10개·데이터 5개 커밋은 이미 한국어·목적 단위였으므로 SHA와 작성자 정보를 그대로 보존했다. 옛 실험 이력의 영어 제목은 현재 작업 이력으로 다시 합치지 않았다.
- 사용자가 추가로 정한 것은 목적별 브랜치 접두사, 불필요한 작업 도구 이름을 커밋/PR에 넣지 않는 것, 완료한 정리를 반복하지 않는 것이다. 구현·확인은 AI가 수행했다. 기존 커밋의 작성자를 바꾸거나 사용자가 실험 정답을 검수했다고 기록하지 않았다.
- 두 저장소의 시작 refs는 로컬 `scratch/finalize-20260910/recovery/`의 검증된 bundle과 manifest로 보존했다. 비공개 bundle을 공개 Git에 넣지 않았고 무시된 모델·실행 파일·캐시·개인 설정은 추가하지 않았다.

## 브랜치와 실험 이력

양쪽 최종 작업 브랜치는 **`refactor/collection-review`**다. 로컬 이름을 바꾸고 같은 HEAD를 일반 푸시했다. 내용이나 커밋을 바꾸는 강제 푸시는 사용하지 않았다.

| 참조 | 용도 |
|---|---|
| `refactor/collection-review` | 이후 검증된 변경을 커밋·일반 푸시할 작업 브랜치 |
| `archive/redesign-evaluation-20260910` | 원래 실험의 코드 `10865a1`·데이터 `aa31313`을 각각 보존하는 태그. 앞선 연구 커밋과 원래 코드 링크도 계속 도달 가능 |
| 옛 원격 `codex/collection-review` | 이동 전 정리 HEAD. 새 브랜치의 조상이며 삭제 확인 대기 |
| 옛 원격 `codex/redesign-evaluation-20260910` | 보존 태그와 같은 실험 HEAD. 삭제 확인 대기 |

보존 태그는 새 실험 결과가 아니다. 동결 파일·manifest·비공개 freeze 지문은 그대로다. 학습 글에 남아 있던 옛 `tests/test_newsroom_study.py` 링크 한 곳만 실제 보존 위치로 고쳤다. 현재 운영 코드가 과거 모델 결과를 냈다는 뜻으로 링크를 바꾸지 않았다.

## 기본 작업 방식과 반영 제안

사용자의 기존 방식대로 목적별 브랜치에서 완결된 한국어 커밋·일반 푸시를 기본으로 한다. PR은 요청이 있을 때만 만들며 데스크탑 앱을 쓴다는 이유로 추가하지 않는다.
코드와 데이터의 main은 각각 `543dbff`·`a567612`에서 출발한 이력을 fast-forward로 반영하는 안을 제안한다. 데이터 로컬 main `9f22daa`는 원격보다 2개 뒤에 있었으므로 그 차이도 빠뜨리지 않는다. 기존 정리 커밋을 squash하거나 다시 작성할 필요가 없다.

코드 main 푸시는 현재 Vercel 설정상 배포 대상이다. 공개 발행 파일을 바꾸지 않아도 파이프라인·표시 동작은 달라진다. 데이터 main 푸시는 검증/연구 자료와 제외 설정을 반영하며 데이터 저장소에는 사이트 배포 workflow가 없다. 두 main 반영, 옛 원격 네 브랜치 삭제, 배포는 각각 사용자의 확인 없이 수행하지 않는다.

같은 날 완료한 Ollama 0.33.3/Qwen 점검은 [기존 기록](../../docs/local-model-audit-2026-09-10.md)을 재사용했다. 수정 버전을 확인하지 못한 취약점을 해결됐다고 바꾸지 않았으며 이번 정리에 추론이 필요하지 않아 모델을 켜지 않았다.

## 같은 기간을 봐도 수집 범위가 다르면 판단이 달라진다

첫 비교는 W36에 후와후와 빵이 없어서 일반 블로그가 기존 수집 밖의 후보를 더할 것이라고 기대했다. 후속으로 8월 10~16일 식품 사례 5종을 고정하고 W33/W35/W36 저장 목록 41개를 대조하니, **우유 쫀득빵은 W35 GS25에 이미 있었다.** W36에는 GS25 관측 자체가 없다. 추가 발견의 근거로 삼았던 해석을 철회하고 후기·구매 경험의 추가 정보로 범위를 좁혔다.

‘솔티버터’에는 다른 회사 와플이, ‘후와후와’에는 황치즈맛 빵도 걸렸다. 문자열 일치가 같은 제품을 뜻하지 않는 사례다. 식품 5종 중 2종에 과거 목록 이름 후보가 있었고 나머지 3종은 찾지 못했지만, 선택 표본의 이 수치를 시장 커버리지나 출시 정확도로 쓰지 않았다. 공식 근거 미확인도 출시하지 않았다는 뜻이 아니다.

기존 8월 말 카페의 호지 라떼·아이스 변형 사례는 별도 기간/범위로 재사용했다. 검색 설명만 확인한 영상, 열지 못한 Instagram·카페는 실측 분모에서 제외했다. 플랫폼 접근 조건은 같은 날 확인한 근거를 재사용했고 운영 수집기를 추가하지 않았다.

[비교 문서](../../docs/collection-route-review-2026-09-10.md)에 세 시험의 입력 범위·확인 질문·채택/보류 조건을 보강했다. 순서는 목록+공식 발표, 일반 콘텐츠→공식 확인, 푸드QR 동일성 조회다. ‘채택’은 후속 비교 확대 제안이며 운영 도입에 대한 사용자 결정이 아니다. API 키 신청·새 유료 서비스·모델 실행도 수행하지 않았다.

## 재사용한 검증과 새로 확인한 것

- 중복 판별과 발행 입력 검증의 실제/합성 반례와 테스트를 읽고 유지했다. 규칙 변경 후 기본 테스트 638개 통과·3개 skip, 스킬 검증과 모든 추적 Markdown의 내부 링크 검사를 통과했다.
- 동결 연구 8개 파일의 SHA-256은 manifest와 그대로 일치한다. 이미 통과한 연구 테스트 26개·평가 재생을 다시 실행해 새 성과로 세지 않았다.
- 웹 트리와 공개 주간 파일이 빌드 성공 시점 `a330078`과 같아 기존 빌드 검증을 재사용했다. 새 `make check-images WEEK=2026-W36`은 6개 소스 53개 표본 전부 통과했다. HEAD/robots 검사이며 이미지 복제·전체 이미지 보증은 아니다.
- 공개 `data/weeks/`와 운영 코드·스크래퍼·소스 설정을 바꾸지 않았고 실제 발행 재생도 하지 않았다. 비공개에는 새 비교 조건·선별 결과·입력 지문을 기존 결과와 별도 파일로 남겼다.

Git 참조와 커밋 객체의 차이는 이름을 옮겨도 SHA가 유지되는 검증에, 관측 부재와 빈 결과의 구분은 GS25 반례에, 비교군 고정은 기간이 다른 자료를 합산하지 않는 데 실제로 쓰였다. 수업에서 배웠다는 사실이나 사용자가 실험을 독립 검수했다는 사실은 제공되지 않아 덧붙이지 않는다. 블로그·포트폴리오에는 ‘새 경로의 증분 가치를 입증했다’가 아니라, AI의 초기 기대를 과거 관측으로 반박하고 비교 범위를 고친 사례로 남길 수 있다.
