# 실제 실패는 막고, 좁아진 실험과 이력을 정리한다

> 2026-09-10 후속: 아래는 첫 정리 완료 시점의 기록이다. 이후 사용자 요청에 따른 목적별 브랜치와 현재 반영 상태는 [후속 기록](2026-09-10-목적별-브랜치와-비교-범위.md)을 따른다. 당시 커밋·판단·검증 결과는 바꾸지 않았다.

목록의 중복 등록과 잘못된 발행 입력을 막는 변경은 남겼다. 기사 추출을 더 개선하는 대신 실패한 실험을 동결하고, 실제 수집 경로를 다시 비교했다. 큰 영어 커밋은 기존 관행에 맞는 한국어 변경 단위로 재구성했다.
이 글은 사용자의 정리 요청을 AI가 조사·구현·검증한 기록이다. 사용자가 코드를 직접 작성했거나 연구 결과를 독립 검수했다고 쓰지 않는다.

## 무엇이 결정돼 있었나

| 구분 | 확인한 내용 |

| AI 판단 | 중복/발행 보호를 유지하고 규칙 사본·사용하지 않는 훅·초기 연구 구현을 줄인다. 보존 실험은 별도 경로로 옮긴다. 후속 경로 3개는 추천이며 운영 도입 결정이 아니다. |

먼저 실제 변경에 근거한 짧은 구성안을 제시했다. 공통 기반 → 발견 판별 → 편집 경계 → 발행 입력 순으로 의존성을 갖추고 각 단계에서 테스트했다. 각 제목은 본문 없이도 달라지는 동작을 읽을 수 있게 썼다.

연구 코드를 단순히 파일 종류별로 분리하지 않았다. 코드·실패 픽스처·측정 기록·승인 조건은 하나의 동결 실험을 재현하는 단위로 묶었다. `manifest.json`이 옛 경로/커밋과 현재 경로를 연결하며, 비공개 `freeze.json`의 원래 코드 지문은 바꾸지 않았다.

데이터는 별도 이력이다. `d466891`을 재설계 비교 근거(`876391b`)와 모델 개발 실험 입력/응답(`354cbbb`)으로 나눴고 `aa31313`의 개발 밖 평가를 `791a22d`로 옮겼다. 이 세 커밋 뒤 데이터 트리는 원래 HEAD와 바이트 단위로 같았다. `2c42c11`은 재현 경로·보안 점검 메타데이터·제외 설정만 추가했다. 이번 비교 검증의 집계·입력 지문도 별도 데이터 커밋으로 남긴다.

최종 작업 브랜치는 양쪽 모두 **`codex/collection-review`**다. 기존 원격 실험 브랜치는 옛 지문과 문서 링크·복구를 위해 남긴다. 기존의 별도 로컬 `backup-before-msg-rewrite`도 이번에 만들거나 고치지 않았다. main·기존 원격 이력을 강제로 바꾸지 않았고 PR을 만들지 않았다.

## 앞으로의 작업 방식과 배운 것

AI 제안은 현재 정리 브랜치에서 검증된 단위마다 한국어 커밋·일반 푸시를 이어가는 것이다. 이력 검토 후 사용자가 main 반영을 결정하면 코드 main 푸시가 배포로 연결됨을 함께 확인한다. 그다음은 기존 직접 커밋·푸시 관행을 유지할 수 있으며 데스크탑 앱을 쓴다는 이유로 PR을 기본값으로 만들지 않는다.

이번에 실제로 쓴 개념은 차집합과 동일성의 차이, 입력 지문과 멱등성, 개발 표본에 맞춘 규칙의 편향, 의존 순서가 있는 커밋이다. 제공되지 않은 수업 내용을 배웠다고 연결하지 않는다. 포트폴리오에는 ‘자동 출시 추출 성공’ 대신 실제 반례를 찾고 실패 결과를 보존하며 범위를 다시 정한 과정을 쓸 수 있다. 자동화율·시간 절감·출시 정확도는 측정하지 않았으므로 성과로 쓰지 않는다.
