## 문제와 결정의 주체

이전 실험의 주장은 AI가 공식 글을 읽어 직접 작성했다. 코드가 연결 후보를 찾았다는 사실만으로 자동 추출 품질을 주장할 수 없었다.
이번에는 본문에서 주장을 만드는 부분을 실제 모델 호출로 바꿨다. 정답 후보는 여전히 AI가 작성했고, 독립적인 사람의 검증은 아니다.

- 사용자 결정: 새 발견과 출시 확인을 구분한다. 공식 출시 사실과 시점이 있어야 출시 확인이다. 시즌 재출시의 공개 범위는 미결정이다.
- 사용자 결정: 구독을 수동 작업에 쓰고 무료 모델을 자동화에 쓰는 방향을 제안한 뒤, **로컬 Qwen3 8B 설치·실험**을 선택했다. 운영 모델 채택은 아니다.
- 확인된 사실: Claude CLI 로그인 상태는 있었지만 실제 호출은 조직의 구독 접근 차단으로 실패했다. 이를 빈 출시 결과로 기록하거나 우회하지 않았다.
- AI 구현 판단: 로컬 HTTP 호출, JSON 검증, 날짜 규칙, 별도 파일 연결을 사용한다. curate·발행·운영 수집 스케줄을 변경하지 않는다.

## 범위와 자료

실제 원문은 기존에 보관한 [스타벅스 8월 27일 발표](https://www.shinsegaegroupnewsroom.com/starbucks-launches-new-hojicha-glazed-tea-latte/) 1편이다.
본문 9문단을 파싱했고 페이지의 별도 AI 요약과 관련 기사는 제외했다. 카탈로그는 기존 W36 스타벅스 사본이다.
새로 발견한 발표가 아니므로 이번 실행의 발견 성과나 기간 커버리지로 세지 않는다.

정답 후보는 명시적인 신규 1건·시즌 복귀 1건, 신규 여부·시점이 충분하지 않은 나머지 제품 6건을 구분했다.
후자의 6건을 ‘출시하지 않은 제품’으로 판단하지 않았다. 자동 결과에 없다는 이유만으로 참 음성으로 계산하지도 않았다.
개발 정답 후보 지문은 `15bf2a089d41ccad77be3b61505acc1c904fe096302b631b35b2fa70cd618d1c`이다.

새 평가 자료의 예정 범위는 SCK COMPANY 분류의 2026-08-01~09-08 전체 게시물이다. 제목으로 출시 글만 고르지 않는다.
목록 최대 5페이지·본문 최대 40개·1회·순차 최소 1초 간격으로 정했고 약관 검토안을 제시했다.
그 승인이 아직 없어 실제 기간별 발견·본문 확보율·최종 평가 문서 수는 **미측정/0편**이다.
목록 파서와 수집 명령은 작성했지만, 실제 목록 HTML과 전체 흐름은 미검증이다. 그 구현을 수집 완료로 표현하지 않는다.

같은 계열의 레시피 변경·판매 국가·매장 한정 등까지 모두 검증한 연결 기준은 아니므로 운영 자동 승인에 충분하다고 결론 내리지 않는다.

## 비교와 실패를 어떻게 셌나

동일 개발 기사 1편, AI 정답 후보의 명시적 메뉴 사건 2건이 분모다. 사건의 이름·종류·날짜가 모두 맞아야 완전 일치로 세었다.

| 방식 | 결과 | 한계 |
|---|---|---|
| 단순 규칙 | 4개 중복 후보, 두 제품을 모두 신규로 적고 날짜는 모두 누락. 완전 일치 0/2, 유용한 연결 0 | 문단 사이의 복귀 설명·날짜 공유를 읽지 못했다 |
| Qwen v1 | 사건 종류는 2건 구분. 날짜 오류 1건·누락 1건. 최초 검증에서 특징 근거 누락으로 1건 거부, 나머지 날짜 보류 | 완전 일치 0/2, 유용한 연결 0 |
| 프롬프트 보강 v2 | 사건 종류는 구분했지만 날짜가 둘 다 틀렸다. 날짜 모순·특징 근거 검사에서 둘 다 거부 | 문장 지시를 추가한 것만으로 해결되지 않았다 |
| Qwen + 코드 보정 v3 | 원시 모델 날짜는 여전히 2건 오류. 코드 보정 후 명시적 사건 2/2 일치, 유용한 계열 연결 2건 | 개발 자료에서 고친 결과이며 최종 평가가 아니다 |

v3에서 코드가 보정한 것은 날짜 2개와 인용한 문단에서 찾을 수 없는 특징 1개다.
없는 특징을 만들어 넣지 않고 해당 특징을 제거했다. 호지차라는 다른 근거가 남아 호지 계열 연결은 가능했다.
모델 원시 JSON과 최초 검증 결과를 덮어쓰지 않았으며, 최종 코드로 다시 읽은 평가는 `*-final-code.json`이라는 별도 산출물이다.
따라서 최종 코드가 과거 출력을 개선한 수치를 과거 버전의 성적으로 쓰면 안 된다.

최종 코드 기준 개발 사례에서 잘못 연결한 사건은 0건, 충분한데 보류한 사건은 0건, 유용한 계열 연결은 2건이었다.
반면 **모델이 잘못 추출한 날짜는 2건**이었다. 전부 보류한 기준선의 오연결 0건은 성공으로 평가하지 않는다.
원문이 충분하지 않은 6개 제품은 여전히 미확인이며 전체 출시 누락률의 분모로 삼을 수 없다.

추가로 AI가 만든 합성 글 3건을 실제 로컬 모델로 처리했다. 할인 행사는 promotion, 금융상품과 본문 명령 삽입은 출시 주장 없음으로 나왔다.
모델에게 호출 도구를 제공하지 않았으며, 응답에 도구 호출이 있더라도 실행하지 않는 회귀 테스트를 추가했다.
이 결과로 모든 프롬프트 공격에 안전하다거나 실제 무관 기사 정확도가 높다고 주장하지 않는다.

## 재현과 비용

실행 환경은 Apple M5·메모리 16GiB, Ollama 0.33.3, Qwen3:8b Q4_K_M이다.
설정은 `temperature=0, seed=41, num_ctx=8192, num_predict=4096, think=false, format=json`으로 기록했다.
v3와 재호출은 동일한 원시 JSON을 반환했다. 저장 출력으로 파싱·연결을 두 번 실행한 결과도 같았다.
새 호출 2번의 일치는 향후 모델 실행의 결정성을 보장하지 않는다. 모델 지문·Ollama·프롬프트·코드·입력 지문을 함께 보관한다.

시작 시 모델 적재와 이후 캐시 상태가 다르고, 통제된 성능 벤치마크는 아니다. 시간 차이를 최적화 성과로 주장하지 않는다.
개발 결과 전체를 검토한다면 최소 사건 2건·날짜 보정 2건·특징 보정 1건과 원문에서 미확인으로 둔 6개 제품을 구분해 봐야 한다.
이는 검토 대상 목록이지 사용자의 실제 검토 시간이나 주간 운영 부담 측정치가 아니다.

`make test`: 672 passed, 3 skipped. 날짜 모순·연말 이동·지원하지 않는 표현·동명 중복·다른 판매 맥락·문서 지문 변경·추출 실패 후 새 발견 유지·전부 보류의 평가 오류 등을 확인했다.
운영 curate 프롬프트는 수정하지 않아 기존 편집 dry-run을 재실행하지 않았고, 이번 별도 연구 명령과 저장 출력 재생으로 검증했다. 테스트 통과를 수집 운영 품질 개선으로 바꾸어 쓰지 않는다.

## 자료 보관과 재실행

비공개 기준 경로는 `/Users/sankim/dev/this-week-taste-data/research/launch-automation-2026-09-10/`이다.
`development/`에 원문·목록 대체 메타데이터·모델 원시 응답·정답 후보·평가를, `synthetic-controls/`에 합성 실험을 보관했다.
`code/`와 `code-manifest.json`은 최종 연구 코드 사본과 지문이다. `history/`에는 최초 실패·규칙 출력과 작업 전 파일 지문을 남겼다.
`development-summary.json`은 집계, `runtime/`·`models/`는 로컬 실행 파일과 모델이다.
원문은 공개 코드 저장소로 옮기지 않았다. `/private/tmp`를 없애도 최종 실험은 위 경로에서 재생할 수 있다. 외부 백업/원격 커밋까지 완료했다는 뜻은 아니다.

저장 출력만 재생하려면 저장소 루트에서 다음을 실행한다. 모델 서버나 네트워크가 필요 없다.

```sh
.venv/bin/python -m scripts.newsroom_study replay \
  --root /Users/sankim/dev/this-week-taste-data/research/launch-automation-2026-09-10/development \
  --run qwen-dev-v3-repeat \
  --catalog /Users/sankim/dev/this-week-taste-data/research/launch-automation-2026-09-10/catalog-W36-starbucks.json
```

위 명령은 본문을 포함한 비공개 결과를 stdout에 내므로 공개 로그에 올리지 않는다. 코드가 바뀌었다면 `code/` 사본과 지문을 기준으로 재현한다.
새 모델 실행은 같은 경로의 비공개 README에 적은 로컬 서버 설정 후 `extract --engine ollama --live --run <새 이름>`으로 실행한다.
기존 이름의 실행 설정이 달라지면 덮어쓰지 않고 실패한다. 원문 지문이 바뀌어도 실패하며, 의도한 변경은 새 실험 경로로 보존한다.

## 추천과 남은 결정

**추가 실험을 추천한다.** 유료 API 없이 본문을 처리하고 실제 카탈로그에 연결하는 실행 가능성은 확인했다.
하지만 개발 문서 1편에서 날짜 오류가 반복됐고 코드 보정에 의존했다. 처리량·다양한 발표 의미·누락·검토 시간은 미확인이다.
운영 도입을 승인할 근거도, 로컬 모델을 중단할 근거도 아직 충분하지 않다.

다음 단계는 이미 제시한 일회성 비공개 수집 검토안 승인 후, 개발에 쓰지 않은 기간 자료의 AI 정답 후보·프롬프트·코드를 고정하고 같은 비교를 수행하는 것이다.
정기 수집·공개 출시 표시·시즌 복귀 공개 범위는 이번 실험에서 확정하지 않는다. 운영 도입 시 AGENTS·ADR·관련 스킬의 구체적 변경안을 먼저 제시한다.
연구 스크립트를 호출하지 않으면 운영 경로에 영향이 없으며, 되돌릴 때는 이번 추가 스크립트·테스트·기록만 분리해 제거한다. 기존 미커밋 작업과 비공개 증거는 보존한다.

## 블로그 초안 — 날짜를 잘못 읽는 모델과 일하는 방법

신상품 서비스에서 새로 발견한 항목과 실제 출시를 구분했지만, 공식 발표를 읽는 작업은 아직 AI의 수작업이었다.
이를 반복 가능한 코드로 옮기기 위해 로컬 Qwen3 8B를 시험했다. 무료 모델의 채택은 비용과 품질을 함께 확인할 실험 대상으로 결정했으며, 운영 도입을 미리 정하지 않았다.

첫 개발 자료에는 두 음료가 있었다. 같은 날 소개했지만 하나는 신규 출시, 다른 하나는 해마다 복귀하는 메뉴였다.
단순 규칙은 두 제품을 모두 신규로 읽었다. 모델은 사건 종류를 구분했지만, 글이 게시된 달을 잘못 적용했다.
지시문을 보강해도 오류가 남았다. 같은 설정으로 다시 실행하면 같은 오류가 반복됐다.

개발 과정에서는 문맥 판단과 달력 계산을 분리했다. 모델은 근거 문단과 사건을 추출하고, 코드는 지원하는 날짜 표현만 계산했다.
날짜를 보정한 기록과 원시 출력을 함께 남겨 모델이 처음부터 맞힌 것처럼 보이지 않게 했다.
카탈로그와는 브랜드·이름·종류·판매 맥락·특징을 대조했고, 메뉴 계열의 근거를 아이스·크기별 출시로 확대하지 않았다.

그 결과 개발 문서의 명시적 사건 2건을 계열에 연결했다. 하지만 이 문서를 보고 설계를 수정했으므로 일반 성능으로 말할 수 없다.
다른 발표의 수집과 최종 평가는 아직 남았다. API 청구는 없었지만 5GB가 넘는 모델 파일과 기기 실행·검토 비용까지 사라진 것은 아니었다.

**작성자 관점 자리:** 로컬 모델의 설치·기기 점유 비용을 받아들인 이유와, 직접 검토한 뒤 느낀 운영 부담을 작성자가 덧붙인다.
AI가 사용자의 생각이나 학습 경험을 대신 서술하지 않는다. 공개 원고에는 원문 전체·비공개 카탈로그·교재를 넣지 않는다.

포트폴리오에 남길 수 있는 사실은 문제 정의와 기술 선택의 사용자 결정, AI가 수행한 구현·실험, 실제 날짜 실패와 보정 추적, 고정 입력 재현이다.
‘출시 정확도 100%’, ‘완전 자동화’, ‘운영 시간 감소’는 아직 근거가 없어 성과 문구로 사용하지 않는다.

학습 연결: [모델 출력과 근거 검증](../til/model-output-and-evidence.md). 시간표에 지난 통계·Python·REST 과목과 진행 중 LangChain이 있다고 해서 사용자의 숙련도를 가정하지 않는다.
