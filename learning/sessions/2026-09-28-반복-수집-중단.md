# 반복 실패를 알리는 대신 실제 수집을 멈췄다

사용자의 결정은 “반복 실패를 해결하고, 해결할 수 없다면 주기적 수집을 중단”하는 것이다.
이번에는 수집기를 고쳤다고 보고하지 않았다. AI가 확인한 범위에서 안전한 정상화를
입증하지 못해 GitHub 주간 수집을 실제로 비활성화했다. 판단은 [ADR-0021](../../docs/adr/0021-pause-recurring-collection.md)에 남겼다.

## 문제 → 조치 → 이유 → 확인

작업 브랜치에는 실행 환경 분리와 GS25 옛 경로 제외가 있었지만 예약 작업은 예전 main을
계속 실행했다. 코드가 준비됐다는 사실과 배포된 운영 상태를 구분해야 했다.
W39 14개 소스 저장 성공과 5개 경로 실패를 로그·실제 관측 주차·데이터 push로 나눠 확인했다.

홈플러스는 새 표본에서도 디저트빵 0건이었다. HTTP 200·SUCCESS를 수집 성공으로 바꿀 수는
없다. 우유 48건, 과자 총 233건 중 첫 페이지 100건을 파싱했지만 전체 수집은 수행하지 않았다.
기존 W35의 디저트빵 8건이 지금 0건인 이유는 미확정이다. 임계값 완화나 카테고리 삭제로
이 검사를 통과시키지 않았다. 이는 기존 [응답의 완전성](../til/response-completeness.md)이
실제로 걸린 사례다. 요청 성공과 관측 범위의 완전성은 다른 계약이다.

홈플러스 표본 원문·robots·분류표·측정 요약은 비공개 데이터 저장소의
`research/collection-pause-20260928/`에 둔다. 공개 저장소에는 개수·접근 결과만 기록한다.
운영 스냅샷·원본·공개 주간 파일을 재생하거나 덮어쓰지 않았다.

GitHub workflow id `340964630`은 2026-09-28 11:57 KST `disabled_manually`,
실행·대기 작업은 0건이었다. 코드 main은 `543dbff`, 데이터 main은 `c5b5d5f`로 유지했다.
정상 소스의 다음 주 자동 수집도 함께 멈춘다. 현재 운영은 개선 완료가 아니라 중단이다.

별도 후속 모니터링 삭제는 자동 승인 검토에서 거절됐다. 수집 중단과 감시 기능 삭제는
승인 범위가 다르다는 이유였다. 삭제를 우회하지 않고, 모니터링을 유지하면서 의도한
중단에는 조용히 종료하고 예기치 않은 활성화·새 실행을 확인하도록 갱신했다.
도구가 갱신 성공과 ACTIVE 상태를 반환했다. 수집을 다시 켜거나 새 수집기를 만들지 않았다.

이번 문서 변경은 기존 한국어 관행에 맞춰 한 커밋으로 남기고 측정 원문은 데이터 커밋으로
분리한다. Git 이력을 재구성하지 않으며 main 반영·PR·배포는 수행하지 않는다.

검증: `make test` 653개 통과·3개 skip, `git diff --check` 통과. 수집기 코드는 바꾸지 않았다.
이 테스트 결과를 외부 수집 정상화로 해석하지 않는다. 중단 상태는 GitHub API로 다시 확인했다.
