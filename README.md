# 이번주맛 (this-week-taste)

한국의 편의점, 마트, 카페, 프랜차이즈 매장, 식품 대기업 자사몰에서 그 주에 새로 나온 식음료를 모아 주 단위로 발행하는 수집 파이프라인과 정적 사이트입니다. 2026년 8월 11일에 시작해 W35와 W36 두 주를 발행했고, 2026년 9월 28일에 반복 실패하는 주간 자동 수집을 중단했습니다. 코드와 데이터, 결정 기록은 그대로 두었습니다.

## 지금 상태

- 발행: 2026-W35(소스 4개, 211건), 2026-W36(소스 17개, 105건). 사이트는 Vercel에 배포했습니다.
- W37은 이 작업 브랜치에 발행안(소스 18개, 121건)으로만 있고 사이트에 반영하지 않았습니다. 승인하지 않은 변경은 운영에 넣지 않는다는 원칙 때문입니다.
- 주간 자동 수집(GitHub Actions `weekly.yml`, 월요일 두 번)은 2026-09-28에 비활성화했습니다. 컴포즈 403, 맘스터치와 파리바게뜨의 robots 제한, GS25의 CSRF 토큰 변경, 홈플러스의 카테고리 건수 이상이 반복됐고, 차단 우회나 검증 기준 완화는 해결이 아니라고 판단했습니다. 재개 조건은 [ADR-0021](docs/adr/0021-pause-recurring-collection.md)에 있습니다.

## 동작

```
snapshot  →  diff  →  curate  →  publish  →  web
전체 목록 저장   지난주와 차집합   LLM 편집       주차 파일 생성    Next.js 정적 사이트
```

- 신상품은 소스의 NEW 라벨이 아니라 매주 전체 목록을 저장해 지난주와 비교한 차집합으로 판별합니다. 이번 주에만 있으면 신상, 지난주에만 있으면 단종 후보입니다.
- NEW 라벨은 실제 신상의 상위집합이라 정밀도 필터로는 쓰지 않고 재현율 채점표로만 씁니다([ADR-0004](docs/adr/0004-source-expansion-gate.md)). 2026-08-24 첫 실측에서 CU 후보 103건 중 오탐 후보는 4건이었고, 4건은 오래된 상품이 목록에 돌아온 재입고였습니다.
- 수집 건수 검증 기준은 고정값이 아니라 직전 주 스냅샷입니다([ADR-0002](docs/adr/0002-category-count-baseline.md)).
- 상품 식별자는 바코드가 아니라 소스의 카탈로그 항목 코드입니다. 전체 5,082건에서 바코드가 16건 겹쳤기 때문입니다([ADR-0001](docs/adr/0001-product-id.md)).
- LLM은 창작이 아니라 판단에만 씁니다. 신제품과 리뉴얼 구분, 중복 병합, 분류와 태그, 짧은 설명입니다.

## 실행

Python 3.12 이상과 Node.js가 필요합니다. 수집 대상 사이트의 robots.txt와 이용약관을 따르며, 요청 간격과 User-Agent 규칙은 `scrapers/base.py`에 있습니다.

```bash
make setup
make test
make collect SOURCE=cu      # 소스 하나 수집: 스냅샷과 diff. 발행은 하지 않습니다
make week                   # 수집한 결과로 주차 파일을 만듭니다
make site                   # 사이트 빌드
```

전체 타깃은 `make help`에 있습니다. 비밀값은 저장소에 넣지 않습니다.

## 작업 방식

구현과 테스트, 수치 측정은 AI 코딩 도구로 했습니다. 방향과 범위, 판별 방식, 식별자, 공개 범위 같은 되돌리기 어려운 결정은 제가 정했고 `docs/adr/`에 남겼습니다. 커밋 메시지는 제가 승인한 것만 올리며 AI 공동 작성자 표기는 넣지 않습니다. AI 사용 범위는 이 문서와 ADR에 적습니다.

## 한계

- 수집이 멈춰 있어 최신 신상품을 보여 주지 못합니다.
- 소스마다 접근 조건이 달라 일부는 행사 목록만 수집됩니다. 전체 카탈로그를 주는 소스는 CU뿐이었습니다.
- 오탐과 누락 측정은 CU 한 곳에서 한 번 한 값이고, 전체 소스에 대한 값이 아닙니다.
