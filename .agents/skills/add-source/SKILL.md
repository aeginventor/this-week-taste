# 소스 하나를 붙인다

[AGENTS.md](../../../AGENTS.md) 4~7장의 계약을 먼저 읽는다.
기존 사용자 승인·targets.yml·정찰 기록을 확인하고 승인된 범위를 다시 묻지 않는다.
새 소스 약관·이미지 이용 방식의 미승인 선택은 구현을 검토 가능하게 만든 뒤 실행 전에 확인한다.
오래된 정찰을 현재 접근 성공으로 간주하지 않는다. 로그인·차단·robots를 우회하지 않는다.
공식 발표 추출은 `research/launch-study-20260910/`에 동결한 연구로 취급하고 운영 소스에 등록하지 않는다.

## 수집 범위를 먼저 확인한다

- 전체 판매 목록과 우리가 추적할 식음료 목록을 구분한다. 신선 원물·잡화 등을 카테고리 단위로 제외한다.
- `all` 응답 하나를 전체로 가정하지 않는다. 던킨·피자헛처럼 탭을 합쳐야 할 수 있다.
- 모든 요청 카테고리의 완전성을 확인한다. 하나라도 실패하면 소스 전체가 실패해야 한다.
- 상품명에 과일명이 있다는 이유만으로 신선 원물로 제외하지 않는다.
- 개별 URL → 실제 목록 URL → null 순으로 source_url을 정한다. HTTP 200만으로 상품 상세라 판단하지 않는다.
- `external_id`는 카탈로그 전체에서 유일성을 실측한다. 바코드는 판매 등록 키와 구분한다.
- 목록이 이미 주는 설명·태그는 보존한다. 상세에 설명이 없는 소스도 있으므로 상세 요청의 값어치를 먼저 확인한다.

## 구현과 검증

다음 파일을 하나의 소스 추가 변경으로 묶는다.

| 파일 | 반영 |
|---|---|
| `sources/targets.yml` | verified 여부·접근 경로·관측 범위·실측 |
| `scrapers/<id>.py` | fetch·순수 파서·CATEGORIES·BOOTSTRAP_COUNTS |
| `tests/test_<id>_parse.py`, `tests/fixtures/` | 허용된 저장 응답으로 골든 테스트 |
| `pipeline/sources.py` | brand·channel·detail·monotonic_key와 필요한 실행 예외 |

기존 소스 3개까지 복사를 허용하고 4번째에 공통화한다. 소스 고유 어휘를 공유 로직에 넣지 않는다.
가격 미상·동명 항목·카테고리 부재·새 보조 키가 공유 코드에서 조용한 오답을 만드는지 확인한다.
그런 반례가 있으면 회귀 테스트를 함께 만든다. 테스트 수 자체를 성과로 세지 않는다.
분류 목록·프롬프트를 바꾸면 `scripts.curate_dryrun`으로 실제 표본을 확인한다.
목록 작성 이후 추가된 소스를 표본에 포함하고 기타 비율만으로 품질을 단정하지 않는다.
코드·규칙·ADR·이 스킬은 관련 변경과 함께 커밋하고 수집 데이터는 비공개 저장소에 별도 커밋한다.
검증된 변경 단위마다 커밋한다. 제목은 기존 한국어 관행을 따르고 이미 승인된 커밋 범위를 다시 묻지 않는다.
작업 브랜치는 fix/·feat/·refactor/·docs/ 등 목적에 맞게 명명하고 AGENTS.md 9장의 커밋·작성자·PR 규칙을 따른다.
푸시는 합의된 작업 브랜치로 수행한다. main 반영·원격 이력 변경·PR·배포는 AGENTS.md 9장의 확인 범위를 따른다.

## 실행 묶음

로컬·Actions 차이는 [ADR-0017](../../../docs/adr/0017-collector-identity.md)을 따른다.
robots의 수집 창은 [ADR-0014](../../../docs/adr/0014-collection-time-window.md)을 따른다.
collector·windowed 값, 실제 cron과 선택 배열을 함께 검사한다. 시각 제한 묶음이 비면 슬롯도 없어야 한다.
스크래퍼 Session에 week와 source_id를 전달해 robots 원본을 남긴다.
기존 스냅샷은 재사용하며 REFRESH=1 없이 다시 수집하지 않는다.

## 발견 판별

[ADR-0018](../../../docs/adr/0018-discovery-and-launch.md)을 적용한다.
주키를 전체 입력에서 먼저 매칭하고 모호한 보조 키를 순서로 소비하지 않는다.
이전 성공 관측의 원본 ID 또는 바코드·정규화 이름·알려진 가격이 모두 겹치면 근거와 함께 보류한다.
이름만 같거나 가격이 없다는 이유로 제품을 병합하지 않는다. NEW·번호·게시일만으로 출시를 확정하지 않는다.
LLM 편집을 출시 검증으로 취급하지 않고 과거 공개 ID·URL을 보존한다.

LLM 응답의 중복 ref·잘못된 타입·채널 밖 분류는 원본 폴백하고 결과를 리포트에 남긴다. 문자열 "false"로 상품을 제외하지 않는다.

## 발행 입력

[ADR-0019](../../../docs/adr/0019-publication-input-integrity.md)에 따라 관측·원본·diff·보강·코드 지문을 검증한다.
이월본을 성공 관측으로 세지 않는다. 옛 부분 파일은 삭제하지 않고 증명 가능 여부에 따라 병합에서 제외한다.
같은 주의 검증된 이전 성공본을 유지하면 수집·생성 시점을 표시한다. 검증 산출물은 격리한다.
